## 章节由谁生成

原先的实现设想：大语言模型一次生成四个章节。

现在的实现选择：

- 大语言模型只生成 `surplusReasons` 和 `pointsToWatch`。
- Java 根据同一次 Monthly Analysis Context 生成 `monthlyOverview` 和 `expenseStructure`。
- Java 再把权威结余事实和模型的结余解释组合成最终的 `surplusReasons`。
- 最终结果仍是四个字段：`monthlyOverview`、`expenseStructure`、`surplusReasons`、`pointsToWatch`。

模型文字不能替换 Java 已经确定的金额、笔数和结余。结构校验失败时不产生成功报告。不进行第二次模型修复调用。

## 模型输入

模型输入只从已读出的 Context 投影，不再查询数据库。允许的字段是 `month`、`timeZone`、`currency`、`unit`、`monthlySummary`、`incomeCategories`、`expenseCategories`、`uncategorized`、`keyExpenseTransactions`。

`unit` 固定为 `元`。不放入账户身份、指纹、快照、提供方、模型、Prompt 版本、First Save Order、Tag 或 BalanceAdjustment。交易名称只作为不可信文本。

## 模型输出

契约版本 `v1`。JSON 对象恰好包含两个非空字符串：`surplusReasons`、`pointsToWatch`。不接受未知字段。字段顺序不影响校验。Trim 后不能为空白。每个字段最长 2000 个字符。

对应 Schema：`src/main/resources/analysis/monthly-analysis-output-schema-v1.json`。

Prompt 初始版本：`src/main/resources/analysis/monthly-analysis-prompt-v1.txt`。本轮不调用模型。
