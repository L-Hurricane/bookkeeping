## 章节由谁生成

原先的实现设想：大语言模型一次生成四个章节。

T6-C1 确认的实现选择：

- Java 根据同一次 Monthly Analysis Context 生成 `monthlyOverview`、`expenseStructure` 和 `surplusReasons`。
- 大语言模型只生成最终报告中的 `pointsToWatch`。
- 模型输出契约仍是恰好两个非空字符串：`surplusReasons` 与 `pointsToWatch`。Prompt 仍是 `monthly-analysis-prompt-v2.txt`，版本 `v2`。
- 模型返回的 `surplusReasons` 不拼接、不保存到最终章节。
- 金额一致性校验只检查最终展示的 `pointsToWatch`。被丢弃的结余字段里的金额错误不使整份报告失败。`pointsToWatch` 中可识别的明确金额矛盾仍按无效输出失败，不保存成功快照，不消耗成功配额，不自动重试。
- 最终结果仍是四个字段：`monthlyOverview`、`expenseStructure`、`surplusReasons`、`pointsToWatch`。

模型文字不能替换 Java 已经确定的金额、笔数和结余。结构校验失败时不产生成功报告。不进行第二次模型修复调用。历史成功快照保持原样，不因本次职责调整被删除或改写。

## 模型输入

模型输入只从已读出的 Context 投影，不再查询数据库。允许的字段是 `month`、`timeZone`、`currency`、`unit`、`monthlySummary`、`incomeCategories`、`expenseCategories`、`uncategorized`、`keyExpenseTransactions`。

`unit` 固定为 `元`。不放入账户身份、指纹、快照、提供方、模型、Prompt 版本、First Save Order、Tag 或 BalanceAdjustment。交易名称只作为不可信文本。

## 模型输出

契约版本 `v1`。JSON 对象恰好包含两个非空字符串：`surplusReasons`、`pointsToWatch`。不接受未知字段。字段顺序不影响校验。Trim 后不能为空白。每个字段最长 2000 个字符。

对应 Schema：`src/main/resources/analysis/monthly-analysis-output-schema-v1.json`。

Prompt 初始版本：`src/main/resources/analysis/monthly-analysis-prompt-v1.txt`。当前 Prompt 是 `src/main/resources/analysis/monthly-analysis-prompt-v2.txt`，版本 `v2`。T6-C1 不修改这段 Prompt 文本。
