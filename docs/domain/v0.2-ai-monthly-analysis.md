本文记录 AI 月度分析已经确认的领域结论。不包含数据库表、API、Provider、指纹算法或生成流程实现。

---

## 1. 领域定位

AI 月度分析是支持能力（Supporting Capability）。

它不修改记账核心（Bookkeeping Core）：User、Account、Transaction、Category、Tag、BalanceAdjustment、Ledger、Statistics 的正式领域定义保持 v0.1 Domain Baseline，以及已接受的可选分类变更。

AI 生成不加入 Transaction 的一致性边界。AI 分析与 Transaction 的生命周期相互独立。编辑或删除 Transaction 不修改已经生成的分析快照。

---

## 2. 账本事实与 AI 解释

两类含义分开：

| 中文 | English | 领域身份 |
|---|---|---|
| 账本事实 | Bookkeeping Facts | 已保存的记账事实，及其既有派生结果。正式财务事实仍由记账核心定义。 |
| AI 推测 / 解释 | AI-generated Interpretation | 对一份分析输入的解释。它不是账本事实，也不能回写账本。 |

AI 解释事实。AI 不重新计算正式财务事实，不修改账本，不定义消费是否合理，不把账本没有的信息写成现实事实，不产生跨月判断。

交易类型（Transaction Type）与有符号金额（Signed Amount）继续相互独立。依据是 v0.1 Domain Baseline 的 Transaction 不变量，以及 v0.1 产品需求 7.2。AI 不得按金额正负跨收入 / 支出重分类。

- `EXPENSE +100`：增加支出 100。
- `EXPENSE -100`：减少净支出 100，类型仍是 Expense。
- `INCOME +100`：增加收入 100。
- `INCOME -100`：减少净收入 100，类型仍是 Income。

---

## 3. 进入分析的事实

分类（Category）是主要分析维度。分类层级沿用 v0.1。未分类（Uncategorized）沿用已接受的可选分类变更：它是缺失分类，不是 Category 实体。

标签（Tag）不进入 AI 月度分析。Tag 的生命周期、关联和标签统计不变。

余额调整（BalanceAdjustment）不进入 AI 月度分析。它仍不是收入或支出，仍不参与收支统计。

关键支出交易（Key Expense Transactions）是支持事实（Supporting Facts），不是新的记账实体，也不改变流水排序。

候选是当前自然月内、`Type = EXPENSE`、`Amount != 0` 的交易。按 `abs(Amount)` 降序取最多 5 条。正支出和负支出都可以进入。每条携带分类、交易名称、有符号金额和业务时间。交易名称保持已保存的值，包括为空。

收入侧不提供关键收入交易（Key Income Transactions）。这是已接受的 MVP 限制，不是未关闭的领域决定。

`Amount != 0` 与现有「普通交易金额必须非 0」一致，不新增 Transaction 不变量。

## 4. 月度分析上下文（Monthly Analysis Context）

身份：**派生输入快照（Derived Input Snapshot）**。

由当前的用户（User）、自然月（Natural Month）和账本事实（Bookkeeping Facts）构建。

一次生成（Generation）开始后，这份输入视为不可变输入快照（Immutable Input Snapshot）。生成过程不跟着之后的账本修改改写同一份输入。

记账核心提供事实。记账核心不为 AI 定义 AI 专用模型。上下文由分析能力自己构建。模块边界见 Architecture 文档；领域上，上下文不是 Transaction、Ledger 或 Statistics 实体。

---

## 5. AI 月度分析快照（AI Monthly Analysis Snapshot）

身份：**不可变生成产物（Immutable Generated Artifact）**。

它不是可变的记账领域实体（Bookkeeping Domain Entity）。

每次成功重新生成，创建新的 Snapshot。

历史 Snapshot：

- 永不修改
- 不重新计算
- 不因为 Transaction 改变而更新
- 不做历史一致性维护

MVP 产品不展示历史列表。保留历史 Snapshot，是为了以后可以展示 AI 分析轨迹。

只有 AI 输出通过生成结果校验之后，才创建 Snapshot。生成失败不删除、不更新、不覆盖已有 Snapshot。校验和失败处理的技术方案不在本领域基线中冻结。

---

## 6. 查询语义与派生状态

最新分析（Latest Analysis）是查询语义（Query Semantic）。它不是独立实体。

历史（Historical）同样是查询语义。历史 Snapshot 没有单独的可变生命周期。

当前 / 过期（Current / Stale）是派生状态（Derived State）。比较：

- 当前上下文指纹（Current Context Fingerprint）
- 最新快照的上下文指纹（Latest Snapshot Context Fingerprint）

不要给 Snapshot 建立可变的 stale 状态。

上下文指纹（Context Fingerprint）是技术 / 应用值（Technical / Application Value）。它用来判断当前账本是否与最新快照的上下文一致，以及相同上下文是否可以复用已有 Snapshot。具体算法尚未冻结，不属于本领域决定。

---

## 7. 配额与新鲜度在领域中的位置

配额（Quota）属于应用 / 运行策略（Application / Operational Policy）。它不进入 Account 或 Transaction 领域。

分析能力自己持有分析专用配额。记账核心不管理它。产品规则见产品基线：每用户每个 `Asia/Shanghai` 自然日最多 3 次成功的新分析。查看、相同上下文复用、空月份、生成失败和无效结果不消耗产品配额。

空月份（Empty Month）是收入交易笔数与支出交易笔数都为 0。此时不调用外部大语言模型，不创建 AI 月度分析快照，不生成 AI 分析。用户看到的语义是当前月份没有可分析收支记录，所指为当前账本中未记录收入 / 支出，不把账本未记录的情况写成用户现实中没有收入或支出。只有收入的月份和只有支出的月份仍然可以分析。这不新增领域决定。

运行成本防护（Operational Cost Guard）与产品配额不是同一概念。当前没有领域模型。

CR-001 分析前数据新鲜度确认（Pre-analysis Data Freshness Check）属于应用一致性规则（Application Consistency Rule）。正式规则见 `docs/changes/v0.2-ai-monthly-analysis-cr-001-pre-analysis-freshness.md`（Status: Accepted）。它不改变 Snapshot 的定义，也不改变账本事实的定义。

## 8. 术语

后续 AI 月度分析文档沿用这些对照。v0.1 领域词典继续有效。

| 中文 | English | 含义 |
|---|---|---|
| 月度分析上下文 | Monthly Analysis Context | 一次生成使用的派生输入快照 |
| AI 月度分析快照 | AI Monthly Analysis Snapshot | 一次成功生成留下的不可变产物 |
| 结构化输出 | Structured Output | 固定四部分的有效分析结果 |
| 模型提供方 | Provider | 外部模型来源。具体厂商未选择 |
| 来源元数据 | Provenance Metadata | 分析产物自有的来源信息。字段未冻结 |
| 上下文指纹 | Context Fingerprint | 比较上下文是否相同的技术值。算法未冻结 |
| 关键支出交易 | Key Expense Transactions | 分析上下文中的支持事实，最多 5 条 |
| 最新分析 | Latest Analysis | 查询语义，不是实体 |
| 当前 / 过期 | Current / Stale | 由两侧指纹比较得到的派生状态 |

有效结构化输出固定为：本月概况（Monthly Overview）、支出结构（Expense Structure）、结余情况与可能原因（Surplus Situation and Possible Reasons）、值得关注（Points to Watch）。

## 9. 已确认结论

1. AI 月度分析是支持能力（Supporting Capability）。
2. 不修改记账核心（Bookkeeping Core）。
3. 账本事实（Bookkeeping Facts）与 AI 解释（AI Interpretation）严格分离。
4. 交易类型（Transaction Type）与有符号金额（Signed Amount）独立。
5. 分类（Category）是主要分析维度。
6. 标签（Tag）不进入 AI 月度分析。
7. 余额调整（BalanceAdjustment）不进入 AI 月度分析。
8. 月度分析上下文（Monthly Analysis Context）是派生输入快照（Derived Input Snapshot）。
9. 上下文在一次生成（Generation）中不可变（Immutable）。
10. 关键支出交易（Key Expense Transactions）是支持事实（Supporting Facts）。
11. AI 月度分析快照（AI Monthly Analysis Snapshot）是不可变生成产物（Immutable Generated Artifact）。
12. 每次重新生成创建新 Snapshot。
13. 历史 Snapshot 永不修改。
14. 最新（Latest）与历史（Historical）是查询语义（Query Semantics）。
15. 当前 / 过期（Current / Stale）是派生状态（Derived State）。
16. 配额（Quota）属于应用 / 运行策略（Application / Operational Policy）。
17. AI 分析与 Transaction 生命周期独立。
18. AI 生成不加入 Transaction 的事务边界（transaction boundary）。
19. CR-001 新鲜度确认属于应用一致性规则，不改变 Snapshot 或账本事实的领域定义。正式规则见 `docs/changes/v0.2-ai-monthly-analysis-cr-001-pre-analysis-freshness.md`。

当前没有未关闭的领域决定（No Open Domain Decision）。
