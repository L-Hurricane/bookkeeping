## 1. Confirmed So Far

### A01 · 分析逻辑模块（Analysis Logical Module）

建立独立的分析逻辑模块。

仍然是一个 Spring Boot、一个 Maven 工程、一个进程。当前不拆微服务。逻辑上使用包边界（package boundary）。本文不指定具体 Java 包名。

### A02 · 月度分析是第一个能力（Monthly Analysis as First Capability）

AI 月度分析是分析模块的第一个具体能力。

内部使用具体模型，例如 `MonthlyAnalysisContext`、`MonthlyAnalysisSnapshot`、`GenerateMonthlyAnalysis`。

当前不把它泛化成通用分析框架（Generic Analysis Framework）。

### A03 · 面向业务的边界（Business-oriented Boundary）

顶层模块使用 `analysis`。

不使用 `ai` 作为整个业务模块边界。AI / LLM 是实现技术。

### A04 · 单向依赖（One-way Dependency）

Analysis 依赖 Bookkeeping 的读取能力。

Bookkeeping Core 不依赖 Analysis。禁止循环依赖（Circular Dependency）。

### A05 · 依赖公开读取边界（Depend on Public Read Boundary）

Analysis 不直接依赖：

- Core Repository
- Persistence Entity
- Internal Calculator
- Database Table

通过稳定的读取边界获取事实。当前方向可以是 `MonthlyAnalysisFactsReader` 这种薄端口（Port）。具体 interface 尚未冻结。

### A06 · 分析模块拥有自己的 AI 数据（Own AI Data）

Analysis Module 自己拥有：

- 月度分析快照（Monthly Analysis Snapshot）
- 上下文指纹（Context Fingerprint）
- 分析专用配额（Analysis-specific Quota）
- 来源元数据（Provenance Metadata）

Core 不管理这些数据。指纹算法、配额实现、来源元数据的内容，以及快照如何持久化，都尚未冻结。

### A07 · 提供方藏在分析边界之后（Provider Hidden Behind Analysis Boundary）

外部 LLM 提供方（External LLM Provider）位于 Analysis 技术边界之后。

应用用例（Application Use Case）不直接依赖具体 Provider 的 API 或 SDK。本文不选择厂商，也不记录密钥。

### A08 · 不预先建立共享 AI 平台（No Premature Shared AI Platform）

MVP 不建立通用 AI 平台（Generic AI Platform）或共享 AI 框架（Shared AI Framework）。

出现第二个真实 AI 能力之后，再从真实重复里抽象。

### A09 · 读取与生成分成两个用例（Separate Read and Generate Use Cases）

至少区分：

- 查看月度分析（Get Monthly Analysis）
- 生成月度分析（Generate Monthly Analysis）

打开页面不等于调用 LLM。

### A10 · 服务器重建当前上下文（Server Rebuilds Current Context）

每次生成，后端必须根据当前账本事实重新构建当前月度分析上下文（Current Monthly Analysis Context）。

前端提供的上下文或指纹不能作为权威账本事实。

### A11 · 应用层负责编排（Application Orchestrates）

应用层（Application Layer）负责编排（orchestration）。

它不重新实现统计（Statistics）、交易汇总（Transaction aggregation）或分类计算（Category calculation）。

### A12 · 事实经过读取端口（Facts Through Read Port）

Analysis 通过稳定的读取端口（Read Port）获取记账事实（Bookkeeping Facts）。

### A13 · 分析模块构建上下文（Analysis Owns Context Construction）

Bookkeeping 提供事实。

Analysis Module 自己构建月度分析上下文（Monthly Analysis Context）。

Core 不为 AI 构造 AI 专用模型。

### A14 · 复用先于配额（Reuse Before Quota）

相同上下文可以复用 Snapshot。

复用判断优先于产品配额（Product Quota）。多条 Snapshot 指纹相同时应选用哪一条，尚未冻结。

### A15 · 提供方藏在生成端口之后（Provider Hidden Behind Generator Port）

应用不直接调用具体模型厂商。

后续提供方抽象评审（Provider Abstraction Review）再冻结具体端口。本文只确认「必须隔着端口」，不确认端口形状。

### A16 · 只有有效生成才创建快照（Only Valid Generation Creates Snapshot）

只有 AI 输出通过生成结果校验（Generated Output Validation）之后，才能创建 Snapshot。

校验规则的实现尚未冻结。

### A17 · 失败不改变已有快照（Failure Does Not Mutate Existing Snapshot）

新的生成失败时，不删除、不更新、不覆盖已有 Snapshot。

### A18 · 用户可见的上下文新鲜度门禁（User-visible Context Freshness Gate）

生成之前，后端必须做新鲜度确认（Freshness Check）。产品规则见 `docs/changes/v0.2-ai-monthly-analysis-cr-001-pre-analysis-freshness.md`（Status: Accepted）。

如果用户当前已查看的上下文与服务器当前上下文不一致，返回 `REFRESH_REQUIRED`，并且：

- 不调用 LLM（No LLM Call）
- 不创建 Snapshot（No Snapshot）
- 不消耗产品配额（No Product Quota Consumption）

具体的新鲜度令牌（Freshness Token）、指纹（Fingerprint）或版本（Version）实现方式尚未冻结。

## 2. 这些决定已经约束、但还没有组成完整方案的点

下列句子已经确认。它们还不是一份冻结的生成流程（Generation Flow）：

- 生成前做新鲜度确认。
- 每次生成由服务器按当前账本事实重建上下文。
- 相同上下文的复用判断先于产品配额。
- 只有校验通过才创建新 Snapshot。
- 失败不改已有 Snapshot。
- 查看用例不调用 LLM。

步骤之间的其余顺序、超时、并发、重试和持久化事务不在本文补写。

空月份（Empty Month）的产品行为已经冻结，见 `docs/product/v0.2-ai-monthly-analysis.md`：收入交易笔数与支出交易笔数都为 0 时，不调用 External LLM，不创建 Snapshot，不消耗 Product Quota，不生成 AI Analysis；提示语义是当前月份没有可分析收支记录，所指为当前账本中未记录收入 / 支出。只有收入或只有支出的月份允许分析。它不是 Open Decision。Controller / API 的 response shape 仍可后续设计，本次不展开。

## 3. 尚未冻结（Open Review）

Architecture Baseline 仍未完成。后续仍需评审，本文不给出方案：

- 提供方抽象（Provider Abstraction）
- 生成流程（Generation Flow）
- 快照持久化（Snapshot Persistence）
- 配额实现（Quota Implementation）
- 缓存 / 指纹（Cache / Fingerprint）
- 失败 / 超时（Failure / Timeout）
- 并发（Concurrency）
- AI 专项设计（AI-specific Design）

同时明确尚未冻结、不得当作已选方案的项：

- 上下文指纹（Context Fingerprint）算法
- 新鲜度令牌、指纹或版本的实现方式
- `MonthlyAnalysisFactsReader` 的具体 interface
- 生成端口（Generator Port）的具体形状
- 来源元数据（Provenance Metadata）的字段
- 运行成本防护（Operational Cost Guard）的实现
- 相同指纹存在多条 Snapshot 时的复用选择

当前没有模型厂商选择，也没有 Provider API Key。
