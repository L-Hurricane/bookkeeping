# v0.3 · Transaction Name Search

Status: Accepted

v0.1 and v0.2 baselines stay as accepted history. This file records only the read added for transaction name search. It does not change bookkeeping semantics, monthly summaries, current balance, or AI monthly analysis.

## Requirement

The ledger page can search the current account's stored transaction names across all history. The match is one contiguous substring. It is not tokenization, semantic search, or a combination of separate keywords.

`牛奶`, `鸡蛋`, and `奶&鸡` match `牛奶&鸡蛋&面包`. `奶鸡` does not.

## API Delta

Existing month-scoped reads stay as they are:

- `GET /api/v1/accounts/{accountId}/ledger?month=YYYY-MM`
- `GET /api/v1/accounts/{accountId}/transactions?month=YYYY-MM`

This change adds one read:

```http
GET /api/v1/accounts/{accountId}/transactions/search?name={keyword}
```

`/search` is a literal path. It must not be parsed as `{transactionId}`.

Rules:

- The caller is the authenticated user. The account must belong to that user. A missing or unowned account is `404 RESOURCE_NOT_FOUND`, same as the other account-scoped reads. No credential is `401`.
- `name` is required after trim. Blank is `400 VALIDATION_FAILED`. Longer than 255 characters is `400 VALIDATION_FAILED`.
- The match field is `transactions.name`. A null or blank stored name does not match, even when the ledger displays a category name.
- The match is a contiguous substring. `LIKE` metacharacters `%`, `_`, and `\` in the keyword are literal characters.
- The SQL text is fixed. The keyword is bound as a parameter. It is not concatenated into the SQL text.
- There is no `month` parameter and no default month window.
- There is no page parameter and no `LIMIT`.
- Balance adjustments are not rows in this response.
- Order is `business_time DESC, first_save_order DESC`.

Response:

```json
{
  "items": []
}
```

Each item uses the existing transaction list item fields: `id`, `type`, `amount`, `displayName`, `category`, `tags`, `businessTime`. `displayName` keeps the existing display rule. Search does not match on that display fallback.

## Non-goals

No pagination, scroll loading, new database, cache, search engine, or migration. Monthly ledger summary and current balance stay on the existing ledger read.
