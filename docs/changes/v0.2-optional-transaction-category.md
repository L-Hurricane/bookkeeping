# v0.2 · Optional Transaction Category

v0.1 baselines stay as accepted history. This file records only the v0.2 delta.

## Requirement

Transaction Category changes from exactly one bookable Category to zero or one.

## Domain Delta

`category_id = NULL` means the Transaction is Uncategorized. Uncategorized is a missing classification, not a Category entity. It is not seeded, has no Category id, and is not part of the Category hierarchy.

Allowed transitions: Category A to Category B, Category A to NULL, NULL to Category A, NULL to NULL. Transaction Type stays immutable.

A present Category must still belong to the current user, match the Transaction Type, and be bookable.

## Architecture Decision

Nullable foreign key. Do not add a system, hidden, or `UNCATEGORIZED` Category.

## Data Delta

`V10__nullable_transaction_category.sql` makes `transactions.category_id` nullable. The composite Category foreign key stays. Existing categorized rows are unchanged.

## API Delta

Create and update `categoryId` may be omitted or null. A Transaction response omits `category` when it is null, under the existing non-null JSON policy.

Category statistics items include `kind` on the top-level item only:

- `CATEGORY` for a real Category group. `categoryId` is present. Children are real categories and have no `kind`.
- `UNCATEGORIZED` for the derived group. `categoryName` is `未分类`, `categoryId` is omitted, and `children` is empty. It is not a child of any Category.

Transaction list drill-down for that group is `uncategorizedOnly=true`. Only the value `true` selects `category_id IS NULL`. `false` and omitting the parameter both leave the filter off. It cannot be combined with `categoryId`. Real Category drill-down remains `categoryId=<id>`. Child `categoryId` is a non-null category id.

A non-null `categoryId` uses the v0.1 canonical hash encoding. A null category is encoded as an empty length-prefixed value, which a category id never produces.

## Statistics Delta

Category statistics are the real Category groups plus the derived Uncategorized group. Their signed amounts together cover that type's monthly Transaction facts. Monthly summary and tag statistics do not depend on whether a Category is present. Uncategorized and Untagged stay separate dimensions.

## Display Delta

`displayName` is the Transaction name, otherwise the Category name, otherwise omitted. The backend does not invent 「未分类」 as a Transaction name.

## Compatibility

Existing categorized Transactions keep their Category, validation, balance, idempotency, and statistics behavior. A null Category and a non-null Category are different idempotent requests.
