# v0.2 · AI 月度分析 · 开发测试数据

Status: Test asset

这套数据只供开发和手工验收使用。它不改变产品、领域或架构规则，也不预先生成 AI Snapshot。

## 隔离

两个专用用户，各有一个固定账户：

| 用户名 | 用途 |
|---|---|
| `AI_ACCEPTANCE_A` | 正常收支、负数支出、负数收入，以及两个空月份 |
| `AI_ACCEPTANCE_B` | 仅收入、仅支出、未分类且无名称的支出 |

不得使用个人正式账号，也不得操作个人流水。脚本只处理这两个精确用户名。凭证写在本机 `$HOME/.config/bookkeeping/ai-acceptance.env`，模式 `600`，不进入 Git。文件里记录用户名、密码和本工具创建后记住的用户 ID。用户 ID 对不上时，脚本停止，不接管同名用户，也不删除后重建。

## 分类映射

预置分类没有「工资薪酬 / 基本工资」和「购物 / 日用品」这两级名称。脚本使用已有可记账分类，并把场景里的细项放进交易名称：

| 场景写法 | 实际分类 | 交易名称 |
|---|---|---|
| 工资薪酬 / 基本工资 | 工资 | 基本工资 |
| 购物 / 日用品 | 购物 | 日用品 |
| 购物退款 | 购物，类型仍是 EXPENSE | 购物退款 |
| 工资冲减 | 工资，类型仍是 INCOME | 工资冲减 |
| 无分类、无名称 | 不传 categoryId | 不传 name |

不新增退款分类。

## 用例

账户期初余额都是 `0.00`。业务时间是北京时间 `+08:00`。

| 编号 | 用户 | 月份 | 记录 | 预期 |
|---|---|---|---|---|
| MA-01 | A | 2026-01 | INCOME 100.00 基本工资；EXPENSE 40.00 日用品 | 净收入 100.00，1 笔；净支出 40.00，1 笔；结余 60.00 |
| MA-02 | A | 2026-02 | INCOME 50.00 基本工资；EXPENSE -20.00 购物退款 | 净收入 50.00，1 笔；净支出 -20.00，1 笔；结余 70.00 |
| MA-03 | A | 2026-03 | INCOME 150.00 基本工资；INCOME -100.00 工资冲减；EXPENSE 20.00 日用品 | 净收入 50.00，2 笔；净支出 20.00，1 笔；结余 30.00 |
| MA-04 | B | 2026-04 | INCOME 12.00 基本工资 | 净收入 12.00，1 笔；净支出 0.00，0 笔；结余 12.00 |
| MA-05 | B | 2026-05 | EXPENSE 40.00 日用品 | 净收入 0.00，0 笔；净支出 40.00，1 笔；结余 -40.00 |
| MA-06 | B | 2026-06 | INCOME 100.00 基本工资；EXPENSE 40.00，无分类、无名称 | 净收入 100.00，1 笔；净支出 40.00，1 笔；结余 60.00 |
| MA-07 | A | 2026-07 | 一笔余额调整，目标余额 10.00，没有收支 | EMPTY_MONTH |
| MA-09 | A | 2026-09 | 没有记录 | EMPTY_MONTH |

MA-07 的目标余额是 `10.00`。账户余额会立刻计入其他月份的收支，所以调整额是目标余额减去当时余额，不是 `10.00` 本身。空月份只取决于这个月没有收支交易。合计 11 笔收支、1 笔余额调整。

## 初始化与验证

```sh
python3 scripts/monthly-analysis-fixtures/fixtures.py plan
python3 scripts/monthly-analysis-fixtures/fixtures.py apply
python3 scripts/monthly-analysis-fixtures/fixtures.py verify
```

三个命令都先确认 `DB_URL` 指向本机的开发库 `bookkeeping`。主机只接受 `localhost`、`127.0.0.1` 和 `::1`。远程主机即使库名相同也会被拒绝。Python 和 Java 启动入口各自检查。Flyway 历史必须已经是成功的 V1–V11。库名不对、有失败记录，或迁移脚本里还有未执行版本时，直接停止。Fixture 进程在启动 Spring 之前设置 `spring.flyway.enabled=false`，因此不会自动升级开发库。正式应用自己的数据源和 Flyway 配置不变。脚本不执行 clean。HTTP 服务只绑定 `127.0.0.1:18080`。

`plan` 只读。它不创建用户、不插入交易、不改表结构，并按月打印已有行数、业务时间和预计动作。MA-07 会单独标出余额调整是复用、待创建还是停止。它也打印这两个用户的 Snapshot 数量。

`apply` 通过检查后才启动专用进程，端口是 `18080`。它使用正式登录、账户初始化、分类、交易和余额调整 API。产品不允许业务时间早于账户创建时间，而公开 API 不能修改创建时间，所以只有在确认需要补齐、且账户 ID 与用户 ID 都属于这两个专用用户时，才把 `created_time` 设为 `2020-01-01 00:00:00`。已有数据不一致时，这一步不会执行。

`verify` 不创建用户。它用月度分析 GET、交易 GET 和余额调整 GET 比对六个月的收支、业务时间、余额调整和空月份。余额调整核对的是接口返回的调整额：目标余额减去当时余额，调整额本身不是 `10.00`。已有 Snapshot 不会让核对失败，`apply` 也不修改或删除 Snapshot。GET 不调用模型。登录会给专用用户写入一条会话，不修改账本。

## 重复执行

月份记录与预期完全一致，包括业务时间，才直接复用。某个月完全没有记录时才补齐，并用固定 Idempotency-Key；同一键再次提交返回已有结果，不另插一笔。已有同名用户如果还带有预期月份之外的交易或余额调整，或者某个月已有一部分、内容不同，`plan` 打印差异，`apply` 和 `verify` 停止。脚本不删除、不覆盖、不补洞，也不清理个人流水或 Snapshot。

工具优先使用已经配置且确认为 Java 25 的 `JAVA_HOME`，以及本机 PATH 上的 MySQL 8 客户端。缺少或版本不符时，再使用 `docs/development/local-environment.md` 里的 Bootstrap 安装。仓库里还没有 `target/classes` 时，先执行 `./mvnw -DskipTests compile`。脚本不下载 JDK 或 MySQL。

## 清理边界

不提供删除命令。不要清空 `bookkeeping`，不要删除个人用户、个人流水、个人分类或已有账户。这两个测试用户的数据只在明确决定废弃整套夹具时单独清理。
