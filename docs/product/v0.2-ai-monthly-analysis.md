## 1. 功能目标

用户选择任意一个自然月（Natural Month）。AI 基于该月账本事实（Bookkeeping Facts）生成一次月度分析。

这是本产品的第一个 AI 推测型（AI Inference-based）能力。产品必须区分：

| 中文 | English | 含义 |
|---|---|---|
| 账本事实 | Bookkeeping Facts | 后端已经确认的记账结果。AI 解释这些事实，不重新计算、不改写。 |
| AI 推测 / 解释 | AI-generated Interpretation | 对当月事实的说明。它不是新的账本事实。 |

业务时间仍按北京时间自然月。本文不改变业务时间、当前余额或流水顺序。

---

## 2. MVP 范围

MVP 只支持：

- 单一自然月（Natural Month）
- 任意月份
- AI 分析结果（AI Analysis Result）
- 无对话（No Chat）

## 4. 分析输入

月度分析上下文（Monthly Analysis Context）使用下列账本事实。

### 4.1 月度总计（Monthly Summary）

- 净收入（Net Income）
- 净支出（Net Expense）
- 结余（Surplus）
- 收入交易笔数（Income Transaction Count）
- 支出交易笔数（Expense Transaction Count）

净收入、净支出、结余和收支笔数的口径沿用 v0.1 产品需求 11.2：净收入是该月收入金额的带符号合计，净支出是该月支出金额的带符号合计，结余是净收入减净支出。起始余额和余额调整不参与这些金额。本文把收入笔数和支出笔数分别放入分析上下文。这不改变 v0.1 月度总计的业务口径。

### 4.2 分类（Category）

- 收入分类统计（Income Category Statistics）
- 支出分类统计（Expense Category Statistics）
- 分类层级（Category hierarchy）
- 未分类（Uncategorized）

分类统计沿用 v0.1 产品需求 11.3，以及已接受的可选分类变更：未分类是缺失分类，不是分类实体。

分类是本能力的主要分析维度。

### 4.3 关键支出交易（Key Expense Transactions）

最多 5 条。每条包含：

- 分类（Category）
- 交易名称（Transaction Name）
- 有符号金额（Signed Amount）
- 业务时间（Business Time）

交易名称明确保留，用于和分类一起分析。AI 可以提示可能存在的分类核对需要。AI 不得自动修改分类。

已保存的交易名称仍按 v0.1 领域规则：名称为空时保持为空，不把分类名称复制成交易名称。

### 4.4 不进入分析上下文

- 标签（Tag）不进入 AI 月度分析。标签统计本身的 v0.1 规则不变。
- 余额调整（BalanceAdjustment）不进入 AI 月度分析。余额调整不参与收支统计的 v0.1 规则不变。

收入侧 MVP 不提供关键收入交易（Key Income Transactions）。这是 **Accepted MVP Limitation**。

## 5. 有符号交易语义（Signed Transaction Semantics）

交易类型（Transaction Type）与有符号金额（Signed Amount）是两个独立业务维度。规则沿用 v0.1 产品需求 7.2 和 v0.1 Domain Baseline。本文不新增金额语义。

- `EXPENSE +100`：增加支出 100。
- `EXPENSE -100`：减少净支出 100。它仍然是支出，不是收入。
- `INCOME +100`：增加收入 100。
- `INCOME -100`：减少净收入 100。它仍然是收入，不是支出。

AI 不得根据金额正负，把收入重分为支出，或把支出重分为收入。

关键支出交易的候选是当前自然月内、类型为 `EXPENSE`、金额不为 0 的交易。MVP 按 `abs(Amount)` 降序取最多 5 条。因此正支出和负支出都可能进入。

这个选择只决定分析上下文中的关键支出交易。它不改变流水的业务时间排序。

金额不为 0 与 v0.1「普通交易金额必须非 0」一致，不是新的交易不变量。

## 6. AI 输出

一次有效的 AI 分析结果固定包含四部分：

1. 本月概况（Monthly Overview）
2. 支出结构（Expense Structure）
3. 结余情况与可能原因（Surplus Situation and Possible Reasons）
4. 值得关注（Points to Watch）

本月概况、支出结构、结余情况与可能原因由 Java 根据同一份权威账务事实生成。值得关注由大语言模型生成。模型仍返回 `surplusReasons` 与 `pointsToWatch` 两个字段；其中 `surplusReasons` 只满足输出契约，不进入最终报告。观察与建议可以有一定模糊，已经能够识别的明确金额矛盾不能作为正常内容展示。展示分析报告时，页面在「值得关注」下方给出固定偏差提示。该提示不由模型生成，不写入快照。

Java 与模型都不做下列事情：

- 不重新计算正式财务事实
- 不修改账本
- 不定义用户消费是否「合理」
- 不把账本未记录的信息当作现实事实
- 不产生跨月判断

只有通过生成结果校验（Generated Output Validation）的输出才成为有效结果。校验的技术方案不在本文冻结。

## 7. 配额（Quota）

每名用户每个北京时间自然日最多成功生成 3 次新的 AI 分析。

时区：`Asia/Shanghai`。

以下不消耗产品配额（Product Quota）：

- 查看已有快照（Snapshot）
- 相同上下文复用已有快照。多条快照都对应该上下文时选用哪一条，本文不指定。
- 空月份（Empty Month）。定义与行为见下文。
- 生成失败（Generation Failure）
- 无效 AI 结果（Invalid AI Result）

CR-001 对生成入口和配额的约定以 Accepted Changes 为准。

配额属于 AI 应用 / 运行策略（AI Application / Operational Policy）。它不进入资金账户（Account）或普通交易（Transaction）的业务规则。

未来的提供方成本保护称为运行成本防护（Operational Cost Guard）。它和产品配额是两个概念。当前不设计其实现。

空月份（Empty Month）是：收入交易笔数（Income Transaction Count）= 0，并且支出交易笔数（Expense Transaction Count）= 0。

此时：

- 不调用外部大语言模型（External LLM）
- 不创建 AI 月度分析快照（AI Monthly Analysis Snapshot）
- 不消耗产品配额（Product Quota）
- 不生成 AI 分析（AI Analysis）
- 用户得到「当前月份没有可分析收支记录」这一语义提示

提示所指的是当前账本中未记录收入 / 支出。不推断用户现实中没有收入或支出。

只有收入的月份（Income-only Month）允许分析。只有支出的月份（Expense-only Month）允许分析。
