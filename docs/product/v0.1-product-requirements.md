# 个人记账软件产品需求文档

**文档版本：v0.1（正式需求基线）**  
**目标产品版本：v0.1**  
**文档状态：已确认**  
**确认来源：v0.1-pm-v2 及最终确认意见**
**历史版本：v0.1-pm-v1 → v0.1-pm-v2 → v0.1 正式需求**

## 一、产品目标

开发一个可实际使用的个人记账产品，支持日常收支记录、账户余额管理、按月查询与分类、标签统计。

产品以多年使用 MoneyWiz 的经验作为需求参考，从较小的功能范围开始，通过 0.x 版本持续完善。

本项目同时用于实践和比较两种 AI 开发方式：

- 放权开发：由 AI 自主推进较完整的开发任务，人在阶段结果上验收。
- 分阶段开发：逐步确认需求、设计、实现和验证。

两种方式使用相同的产品规则和验收标准。开发方式不改变产品范围。

## 二、核心使用流程

登录 → 设置资金账户起始余额 → 记录收入或支出 → 查看流水、统计和余额 → 必要时调整余额。

v0.1 面向个人独立使用，不支持家庭共享或多人协作。

首个客户端为微信小程序，Web、iOS、Android 客户端属于后续版本。

## 三、术语与基本口径

### 3.1 用户账号

用于识别使用者、登录和确定数据归属。

用户账号与微信等第三方登录身份分开，后续可扩展登录方式。

### 3.2 资金账户

用于表示资金所在位置，例如微信、支付宝、工商银行。

v0.1 每个用户仅有一个名为“微信”的资金账户。它是手工记账账户，不连接微信支付，不自动读取外部账单或余额。

### 3.3 余额

根据起始余额及全部已保存流水计算的余额。

余额包含未来日期的交易，仅由本系统内的起始余额及记录计算，不与外部账户核对或同步。

### 3.4 交易时间

用户为交易填写的业务时间，用于确定流水顺序、查询范围及统计月份。

交易时间不决定交易是否影响余额。

## 四、版本范围

### 4.1 本期包含

1. 用户名密码登录与退出。
2. 单一资金账户与起始余额。
3. 收入、支出流水的新增、查看、修改、删除。
4. 固定的一级、二级收支分类。
5. 收支标签选择及随用随加。
6. 当前余额。
7. 余额调整记录的创建、查看、删除。
8. 按自然月查询流水。
9. 月度总计、分类统计、标签统计。

### 4.2 本期不包含

- 公开注册、找回密码、第三方登录及账号绑定。
- 多资金账户创建和账户间转账。
- 家庭共享、多人协作、角色权限。
- 分类新增、改名、删除、移动、合并。
- 标签改名、删除、合并。
- 待确认交易状态及自动状态处理。
- 银行、微信等账单同步。
- 多币种与汇率换算。
- 股票、基金等资产管理和估值。
- 信用卡账期、还款日等专用模型。
- 预算、定期交易、复杂图表。
- 自定义时间范围及高级查询。
- 导入导出、OCR、语音、AI 记账。
- 余额调整记录的修改与历史时点对账。

## 五、用户账号与数据归属

### 5.1 登录

v0.1 使用预先创建的用户名密码账号进行登录，提供退出功能。

账号准备属于部署环节，不提供面向用户的注册和账号管理页面。

后续可接入微信、手机号、支付宝等登录方式，不应因此改变既有业务数据的归属。

### 5.2 数据隔离

资金账户、交易、分类和标签均归属于用户。

用户只能查看、选择、修改和删除自己的数据。不同用户可以拥有同名分类和标签。

本期不实现家庭成员的数据共享或分类、标签整合。

## 六、资金账户

### 6.1 初始化

首次使用时初始化唯一的“微信”资金账户，并填写起始余额：

- 币种固定为人民币。
- 起始余额默认为 0。
- 支持正数、零和负数。
- 最多两位小数。
- 不计入收入、支出和月度收支统计。

初始化完成后，不提供直接修改起始余额的入口。后续差异通过余额调整处理。

### 6.2 余额计算

**余额 = 起始余额 + 收入金额合计 − 支出金额合计 + 余额调整金额合计**

所有金额保留正负号。

全部已保存交易均参与余额计算，不受交易时间是否晚于当前时间影响。

### 6.3 扩展边界

每条流水必须关联明确的资金账户。

本期不开放新增资金账户及转账功能。后续转账应同时影响转出、转入账户，不增加总资金，也不计入普通收入和支出。

本期不提前实现完整转账流程。

## 七、收入与支出流水

### 7.1 字段

普通收支流水包含：

- **类型**：必填，收入或支出。
- **金额**：必填，允许正数或负数，不允许为 0，最多两位小数。
- **资金账户**：必填，本期自动使用唯一账户。
- **交易分类**：必填，每笔选择一个可记账分类。
- **标签**：选填，允许为空，每笔允许多个，同一标签不可重复选择。
- **交易时间**：必填，默认当前时间。
- **备注**：选填。

分类和标签必须与交易的收入、支出类型一致。

### 7.2 正负金额规则

收入、支出代表业务归类，正负号表示该类活动的正向或反向结果。

- 收入 +100：余额增加 100，收入合计增加 100。
- 收入 -100：余额减少 100，收入合计减少 100。
- 支出 +100：余额减少 100，支出合计增加 100。
- 支出 -100：余额增加 100，支出合计减少 100。

例如：

- 打麻将输 100 元：娱乐分类下的支出 +100。
- 打麻将赢 100 元：娱乐分类下的支出 -100。

系统不根据金额符号自动改变交易类型。

股票浮亏等资产估值变化不属于本期功能，不以普通资金流水替代资产估值模型。

### 7.3 时间与确认状态

- 交易时间不得早于资金账户创建时间。
- 可以选择过去、当前或未来时间。
- 本期全部交易为已确认。
- 保存后立即影响余额。
- 流水和统计归入交易时间所属的自然月。

例如，今天录入一笔下个月的支出，它立即减少余额，但只计入下个月的支出统计。

后续版本可增加未来交易自动设为待确认的能力，但已确认、待确认交易均影响余额。用户自行管理提前录入交易的含义。

### 7.4 新增

保存成功后，流水、余额及相关统计保持一致。

保存失败时明确提示，不得出现部分生效；保留用户填写的内容以便重试。

一次保存操作不得因重复点击产生多笔交易。

### 7.5 修改

允许修改：

- 收入或支出类型。
- 金额。
- 分类。
- 标签。
- 交易时间。
- 备注。

更改类型时，必须重新校验分类和标签，不得保留与新类型不匹配的关联。

修改金额或类型后，正确更新余额影响；修改交易时间后，正确更新所属月份。

### 7.6 删除

删除前二次确认。

删除后，撤销该笔流水对余额和统计的影响。本期不提供回收站或恢复入口。

## 八、分类

### 8.1 分类结构

分类区分收入、支出，最多两级。

- 没有二级分类的一级分类，可以直接关联交易。
- 已有二级分类的一级分类不能直接关联交易。
- 交易只能关联其二级分类。
- 二级分类不能继续创建下级分类。

未来开放分类管理时，已经关联过交易的一级分类不允许再创建子分类，避免历史统计口径变化。

### 8.2 名称唯一性

唯一性仅在同一用户内约束：

- 一级分类名称唯一，收入、支出之间也不能重名。
- 同一父分类下的二级分类名称唯一。
- 不同父分类下的二级分类可以重名。
- 分类名称与标签名称分别检查，允许分类与标签同名。

名称去除首尾空白后不得为空，唯一性检查使用去除首尾空白后的名称。

### 8.3 本期固定分类

每个用户初始化以下分类，不提供管理入口。

**收入：**

- 工资：可直接记账。
- 奖金：可直接记账。
- 其他收入：可直接记账。

**支出：**

- 餐饮：早餐、午餐、晚餐、其他。
- 交通：公共交通、打车、其他。
- 购物：可直接记账。
- 居住：可直接记账。
- 娱乐：可直接记账。
- 医疗：可直接记账。
- 其他支出：可直接记账。

“餐饮”和“交通”只用于分组，交易分别关联其二级分类。二者均可拥有名为“其他”的子分类。

## 九、标签

### 9.1 基本规则

- 标签区分收入、支出。
- 标签不支持层级。
- 每笔交易可以没有标签，也可以选择多个标签。
- 标签不改变交易金额、分类或余额计算方式。

### 9.2 随用随加

用户录入交易时，可以选择已有标签，也可以新增当前收支类型的标签。

本期不提供改名、删除、合并和专门的标签管理功能。

### 9.3 名称唯一性

同一用户下，标签名称全局唯一，不因收入、支出类型而分别允许重名。

例如，已有收入标签“奖励”，则不能再创建支出标签“奖励”。

名称去除首尾空白后不得为空。重复创建时提示已有标签；只有类型匹配的已有标签可以被当前交易选择。

## 十、余额调整

### 10.1 创建方式

用户输入调整后的目标余额，系统展示：

- 当前余额。
- 目标余额。
- 本次调整金额。

**调整金额 = 目标余额 − 当前余额**

用户确认后生成余额调整记录，可填写备注。

- 目标余额允许正数、零和负数，最多两位小数。
- 调整记录中的调整金额必须非零，可以为正数或负数。
- 目标余额与当前余额相同时，不创建调整记录，并提示无需调整。
- 账户余额允许为 0；非零限制仅针对调整记录中的调整金额。

例如，当前余额为 100 元，目标余额为 0 元，生成 -100 元调整记录，调整后账户余额为 0 元，此操作有效。

### 10.2 调整记录

调整记录包含：

- 资金账户。
- 带正负号且非零的调整金额。
- 调整时间，固定为本次操作时间。
- 备注。

它是独立的记录类型：

- 影响余额。
- 在流水中可见，并标注“余额调整”。
- 不关联收支分类或标签。
- 不计入收入、支出、分类或标签统计。

### 10.3 保存差额，而非锁定余额

调整记录保存固定差额。

例如，余额为 1,000 元，目标余额为 950 元，生成 -50 元调整记录。

之后补录、修改或删除其他交易时，原来的 -50 元不会自动改变，账户余额也不会被永久锁定为 950 元。

### 10.4 修改与删除

- 每次调整独立提交，账户可进行多次调整。
- 本期不支持修改已保存的调整记录。
- 支持二次确认后删除，删除会撤销其余额影响。
- 如需重新调整，输入新的目标余额，创建新记录。

不支持回到历史日期执行余额矫正。

## 十一、流水查询与统计

### 11.1 月度查询

- 按自然月查询，默认本月。
- 允许查看历史月份和未来月份。
- 按交易时间倒序显示。
- 月份边界统一使用北京时间。
- 本期不支持自定义日期范围。

月度明细包含收入、支出和余额调整。

列表展示类型、金额、分类或调整标识、交易时间；详情展示完整字段。

### 11.2 月度总计

展示：

- 收支交易笔数：收入、支出记录数量，不包含余额调整。
- 净收入：该月收入金额的带符号合计。
- 净支出：该月支出金额的带符号合计。
- 收支结余：净收入 − 净支出。

起始余额和余额调整均不参与上述金额统计。

当前余额独立展示，不因选中的月份变化。

### 11.3 分类统计

在所选自然月内，收入和支出分开统计。

每个分类展示交易笔数与带符号的金额合计：

- 无子分类的一级分类，统计直接关联交易。
- 有子分类的一级分类，汇总其全部二级分类。
- 支持查看二级分类统计及对应交易明细。
- 总计不能将一级汇总与二级明细重复相加。

### 11.4 标签统计

在所选自然月内，按标签展示交易笔数、带符号金额合计及对应明细，收入与支出分开。

一笔交易有多个标签时，完整计入每个标签，不按标签数平分金额。

因此：

- 不同标签统计可能覆盖同一笔交易。
- 标签金额不能相加当作总收支。
- 整体收支总计按交易去重计算。
- 无标签交易仍计入月度总计，并提供“无标签”统计分组。

页面应说明标签统计存在重复覆盖。

## 十二、最小交互范围

至少覆盖：

1. 登录与退出。
2. 设置起始余额。
3. 查看当前余额。
4. 月度流水与总计。
5. 新增、编辑、查看、删除收支流水。
6. 选择分类。
7. 选择或新增标签。
8. 查看分类和标签统计及关联明细。
9. 创建、查看、删除余额调整记录。

不要求每项对应独立页面，具体布局在交互设计阶段确定。

输入未来日期时，应明确提示该交易保存后将立即影响余额。

## 十三、数据与质量要求

- 数据持久保存，退出、重启及重新登录后仍存在。
- 所有数据访问均按用户隔离，不能仅依赖页面隐藏。
- 登录密码不得明文保存。
- 金额计算精确到分。
- 交易保存、修改、删除与余额变化保持一致。
- 保存失败不留下部分生效的数据。
- 重复点击保存不产生重复记录。
- 删除前明确提示其对余额的影响。
- 交付可在手机上实际使用的版本。
- 使用真实数据前，具备可执行的备份及恢复办法。

公开发布涉及的渠道条件不在本文中展开，应在发布准备阶段另行核实。

## 十四、核心验收场景

### 14.1 金额与余额

在同一个自然月依次操作：

1. 设置起始余额 1,000 元：余额为 1,000，收支统计均为 0。
2. 新增支出 +100：余额为 900，净支出为 100。
3. 新增支出 -30：余额为 930，净支出为 70。
4. 新增收入 +200：余额为 1,130，净收入为 200。
5. 新增收入 -50：余额为 1,080，净收入为 150。
6. 将余额调整为 1,000：生成 -80 调整记录，净收入仍为 150，净支出仍为 70，结余仍为 80。
7. 删除该调整记录：余额恢复为 1,080，收支统计不变。

### 14.2 余额调整的零值规则

- 当前余额为 100 元，目标余额为 0 元：允许保存 -100 元调整记录，账户余额变为 0 元。
- 当前余额为 -100 元，目标余额为 0 元：允许保存 +100 元调整记录，账户余额变为 0 元。
- 目标余额与当前余额相同，包括二者均为 0：不创建调整记录，提示无需调整。
- 不允许保存调整金额为 0 的余额调整记录。

### 14.3 未来交易

- 录入下个月支出后，立即减少余额。
- 本月统计不包含该交易，下个月统计包含。
- 本期交易状态为已确认。
- 早于账户创建时间的交易不能保存。

### 14.4 修改与删除

- 修改金额或类型，余额和统计正确变化。
- 修改交易月份，交易从原月统计移至新月统计。
- 删除收支流水，撤销其余额和统计影响。
- 改变收支类型后，不允许保留不匹配的分类或标签。

### 14.5 分类与标签

- 不选择任何标签也可以保存交易，且余额、月度总计和“无标签”分组统计正确。
- 有子分类的一级分类不能直接记账。
- 无子分类的一级分类可以直接记账。
- 不同一级分类下允许出现同名二级分类。
- 同一用户不能创建重名标签，即使收支类型不同。
- 不同用户可以拥有同名标签。
- 一笔 100 元交易关联两个标签，每个标签统计均为 100 元，整体总计仍为 100 元。

### 14.6 查询与可靠性

- 流水按自然月、交易时间正确归属和排序。
- 余额调整在明细中可见，不进入收支及分类、标签统计。
- 重新登录后数据完整。
- 其他用户无法查看或操作这些数据。
- 重复点击一次保存操作，不产生多笔记录。

## 十五、后续演进方向

以下为已知方向，不代表本期交付承诺，也不预设具体版本顺序：

- 多资金账户与转账。
- 分类和标签管理。
- 待确认交易。
- 余额调整差额修改。
- 自定义时间范围。
- 多种登录方式。
