## 2. 导航、页面与交互共识

### 2.1 导航与入口

- 小程序主导航：**账本 / 统计 / 我的**；AI 分析从统计的二级入口访问。
- 账本显示正常账户总览，可以切换并进入单个账户流水；提供账户创建及账户管理入口，另可访问归档账户。
- 账本及单账户流水保留清晰的“记一笔”“转账”入口；余额调整属于账户次要动作。
- “账户管理”用于账户集合；单账户内部的“管理”统一显示为**账户设置**，仅针对当前账户。
- 统计端：按时间与资金账户筛选，分账本净值、收入分析、支出分析；收支各提供分类、标签的独立等权入口。不得让四个入口出现毫无业务意义的黑底选中态。

### 2.2 交易录入、保存与返回

- 用户点普通流水行，直接进入**可编辑的交易表单**；不必再从只读详情点击“编辑”。
- 编辑表单保留“删除交易”入口及必要确认操作；保存后**直接返回交易当前所属资金账户的流水列表**，沿用 v0.1 操作习惯。变更账户后返回新账户列表。
- 新增交易可以选择正常账户；编辑时可以修改所属账户；归档账户不能用于新增业务。
- 分类可不选，选则只允许叶子节点；标签可多选、取消、父子同时显式选中；保存后再次进入应还原实际选中的标签。
- 收入/支出类型在已保存交易中只读；错误或取消保留 v0.1 反馈原则。
- 转账支持转出/转入两个不同账户、两侧业务时间默认同步/可拆分/可恢复同步；保存后返回对应账户列表，转账整体可修改及删除。

### 2.3 账户生命周期

- 创建普通/信用账户后，在账户列表能找到，并可进入其流水。
- 账户归档立即从正常账户列表移除；在归档管理仍可查看历史与恢复；恢复后再次出现。
- 归档账户历史只读；需继续编辑关联交易或记账先恢复。
- 永久删除必须显示受影响交易/转账及关联账户余额前后变化，并经过确认，不可简单做无提示删除。

### 2.4 统计与 AI

- 统计时间常用“本月、本季度、本年、自定义”；账户范围可选正常、包含归档及自定义。
- 分类、标签支持按层级下钻及查看明细；继承筛选条件。分类含未分类，标签父子合并去重、分布允许重叠。
- AI 仅按自然月/自然年分析全部正常及归档账户，具有报告复查入口及每日3次调用额度提示；与普通统计筛选分离。

## 3. 视觉语义

- 主视觉继承 v0.1 已批准的**清晰、克制、轻金融工具型**风格；淡色背景、白色内容层、有限主强调色，保留紧凑易识别的金额/流水布局。
- **所有金额显示统一采用正数红、负数绿、零值中性**；依据金额的数学符号，而**不是收入/支出业务类型**来选颜色。这一规则覆盖首页余额、信用账户、流水、交易表单、转账、余额调整、统计等所有显示金额的界面。
- 金额正负符号、类型文字及语义标识同时保留，不得只依赖颜色传达业务含义。
- 流水行金额保持独立布局；名称、时间、分类等较长信息合理省略/排列，避免挤压金额造成错位或不合理折行。
- 分类与标签统计入口同级、等权；非当前页面内的互斥选择组件，不应保留虚假的常驻选中颜色。

## 4. 余额调整：明确保留旧版历史功能约束

- **已经保存的 BalanceAdjustment 不提供编辑功能**；如需更正，按照已确认旧规则先删除并重新创建调整记录。
- 创建余额调整仍支持输入目标余额、计算差额、填写时间与备注；余额调整差额是已保存的固定业务事实。
- 点击现有余额调整历史记录应能**查看与删除**，而不能误表示为可编辑的普通交易。此项经本轮 Review 认可，**不是 UI 缺陷，不新增“修改已保存余额调整”功能**。

## 5. 原型与真实交付区别

原型使用浏览器 HTML、演示用数据和模拟交互。**不可把原型视为真实小程序或后端功能验收结果**：实际数据库保存、微信身份、跨账户隔离、批量/并发删除、真实统计计算、接口报错及模型调用仍须在开发中落实并测试。

## 6. 后续阶段交接与受控变更

1. 将《PRD v0.2》、本 UI Freeze、旧版产品/架构/领域文档作为审核输入。
2. **真实代码审查**：确定已有实现现状、差异、风险与可复用资产；不依据原型判断已有代码功能。
3. 技术方案与差异分析 Review；再形成 Stage Plan 和完整 Task Plan 并经用户审批。
4. 任何需求或 UI 基线改变，先明确差异、影响和必要性，获得用户认可后更新基线；不得借工程实施隐性加入新功能。
