## 1. 产品与运行目标

1. 在负责人现有 Mac 本地运行 1～3 个月，自用，**无互联网入站访问、无公众用户、不租云主机**。
2. 无须每次打开 Cursor 或重新 Maven 编译：使用固定 SHA 的 JAR、独立运行配置和最少 `bk start|stop|status|backup` 命令；运行版不随 v1.1 开发代码变化。
3. 手机只需家庭 Wi-Fi 可用。二维码可在每次会话重新预览，不追求发布正式小程序或手机脱离 Wi-Fi 可访问；二维码/小程序前端更新与后端数据持久化相互独立。
4. **数据稳定优先于手机入口便利**：独立正式用户及账本库、最小权限、配置与凭据隔离、可验证的备份+恢复、故障后不丢账务关系；不把“进程活着/生成了 dump”冒充数据可靠。
5. 首批 MoneyWiz 导入 1～2 个真实账户；先合成样本验证导入与对账，再对真实记录逐次专项授权，不把跨账户转账扁平化为收支。
6. Mac 睡眠/关机时手机不可连接是接受的；要求持久数据在重启后可恢复，而**非 24 小时不间断服务**。

## 2. 最小部署构造（候选，须真机实测）

```
手机微信小程序（按需扫码预览，仅同一家庭 Wi-Fi）
    ↓ 家庭 LAN，安全 HTTPS/TLS 候选，必须真实手机验证
只监听 Mac 指定 IPv4 网卡的受限入口（源 IP/防火墙+认证+路径白名单）
    ↓ 固定上游 127.0.0.1:18090
独立固定版 Spring Boot JAR / 外部配置（不依赖 Cursor）
    ↓ MySQL 127.0.0.1:3306，独立用户和库
bk_personal_local（正式个人账本，待授权创建）
    ↓ 本地一致性备份 + 加密独立副本 + 隔离库恢复演练
```

**部署选择**：优先复用本机现有 MySQL 服务，同时独立 `bk_personal_local` 库、专用账户、备份目录和权限；这是逻辑隔离而不是进程/磁盘隔离。若实测发现开发与正式操作共享实例构成不可接受的写入/误迁移风险，再提出独立 MySQL 进程的最小专项，不默认新建容器平台。

**LAN 安全必须有证据**：绑定指定 IPv4 地址而非 `0.0.0.0` / 全 IPv6；MySQL 与真实后端仅回环；通过防火墙/等效可验证的主机规则限制手机来源并关闭不必要接口，保留正常账号鉴权。核查路由器 WAN 端口映射、UPnP/IPv6 等外部可达性；由于“不得对外提供服务”是正式要求，不能沿用先前**仅合成数据**获批的跳过 WAN 核查例外。做不到确定无公网入站时禁止正式真实数据手机入口，后端本机运行/离线导入设计可继续。

**传输优先方案**：合成数据先测试本地 HTTPS（证书/信任链与微信真机 request 白名单需要核证）。若本地 CA 被微信拒绝，才做最低成本的域名 DNS-01 公信证书与仅 LAN 可解析路由等方案比较；DNS-01 无需向公网打开 80/443，但可能需要域名和 DNS 管理，须单独成本/权限决定。**不得以 HTTP 明文传真实登录凭据/账务数据，不得在真机限制失效时偷偷 `urlCheck=false`。**

**固定运行制品**：固定已经由原 Stage/独立 Gate 支持的源码 Git SHA，源码、JAR SHA、配置版本分别留证。Java/JDK 路径与实际 Mac 环境一致，避免 `java` 指向错误版本。优先 Spring `additional-location` 或已复核完整配置，不以候选 `config.location` 覆盖必要安全属性。生产配置显式白名单校验；Flyway 在初始化以外禁自动运行；未经审批不得启动时自动变更已存真实 Schema。

### 必备门禁（不额外增加独立 Gate）

- 每项 Coding Task 本地自测、有证据记录。既定一次综合独立 Testing/Supervisor 质量 Gate 复用，不复制 S6 全量重复测试。
- **M1｜先保证启动可用**：T01/T02 已在合成环境验证独立启停、LAN 安全登录、数据持久化、备份和隔离恢复，无 P0/P1，完成既定独立 Testing/Supervisor；达成后提交 T03 空个人正式环境的具体安全/恢复批准。**T04 导入适配不得抢在 M1 前。**
- **个人空账本可用判定（T03）**：专项批准并完成一次正式库初始化后，固定版与独立个人空库启动、重启、健康检查和备份恢复实测成功；用户仍不导入真实 MoneyWiz 数据。这一环节不能从 M1 自动获得写权限。
- **M2｜后迁移数据**：T04 合成导入可复现且通过差异校验；T05 在独立真实数据专项批准后才实施，个人 DB 与首批导入对账由负责人实际验收。不得将合成 Gate PASS 代替本人资金核验。
- P2/P3 不阻断时进 Backlog；不为长期平台/CI/CD/云化增加 Task/Gate。

## 4. 完成标准与停止条件

- 不开 Cursor 即可独立 `bk start/status/stop/backup`，运行版只使用固定 SHA 和隔离配置/数据库；停止后数据仍存在，再启动账务一致。
- 手机在指定家庭 Wi-Fi 可访问，必要时重复扫码，但**没有任何外网服务入口**，登录/账务传输受到保护；检查 IP 来源与微信开发版真正运行行为，不用模拟源 IP 代替实测。
- 备份可在另一隔离库恢复，通过账户数、交易数、转账/余额调整关系、关键余额与校验；可恢复副本独立且加密；用户无须 24h 开机。
- 真实数据初始化前确认正式库与测试库不会误互通，正式配置不会隐式执行 Flyway；迁移前后对账达到批准的精度；无跨用户泄露、无错账/不可恢复异常。
- 无云端部署、无公网上线、无新用户入口、不对其他人提供服务、无 v1.1 编码授权。

STOP：无法核实稳定源码与 Git Gate；本地端口/配置/凭据冲突；不受信任 TLS/微信预览无法安全联通；无法确认外网不可达；备份/恢复未经验证；正式库身份或导入源数据范围不明；P0/P1、越权/不可恢复风险。仅停受影响工作，已合法的合成脚本开发可继续。
