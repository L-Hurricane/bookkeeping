## 1. 版本功能范围

v0.3 在 v0.2 基线上只增加当前账户的交易名称搜索。

已接受变更：`docs/changes/v0.3-transaction-name-search.md`，Status: Accepted。

包含：

- 独立的交易名称搜索读取。
- 当前账户的全部历史交易，没有月份窗口。
- 对已保存名称的连续子字符串匹配。
- `LIKE` 特殊字符 `%`、`_`、`\` 以及转义字符 `!` 按字面量匹配。
- 用户与账户归属校验。
- 微信小程序账本页搜索框。
- 搜索请求的代次保护，过期响应不写回页面。
- 月度流水与搜索结果分开保存；清空关键词后回到所选月份流水。
- 交易编辑或删除返回后，仍有关键词时刷新搜索。
- 前后端对应测试。
- Mock 白名单断言改为无序集合比较。这一处不改变分析行为。

不包含多账户、分页、无限滚动、Redis、MQ、新搜索引擎、AI 分析业务修改，以及新的数据库迁移。

## 2. Accepted API 变更

新增：

```http
GET /api/v1/accounts/{accountId}/transactions/search?name={keyword}
```

`/search` 是字面路径，不作为 `{transactionId}`。

规则以已接受变更为准：登录用户只能搜自己的账户；账户不存在或不属于该用户时 `404 RESOURCE_NOT_FOUND`；未登录 `401`。`name` 去空白后必填，空值或超过 255 个字符为 `400 VALIDATION_FAILED`。只匹配 `transactions.name`。空名称不因分类展示名而命中。没有 `month`，没有分页，没有 `LIMIT`。余额调整不在结果里。排序是 `business_time DESC, first_save_order DESC`。

响应是 `{ "items": [] }`。每一项沿用现有交易列表字段。

既有月份流水和交易列表读取保持不变。

## 3. 主要实现

后端在 `TransactionController` 增加 `GET /search`，由 `TransactionService.searchByName` 执行。关键词作为参数绑定。`LIKE` 模式由 `likeContainsPattern` 生成，SQL 使用 `ESCAPE '!'`。

小程序由 `searchTransactionsPath` 拼出同一路径。账本页用搜索代次判断响应是否仍对应当前账户和当前关键词。月度流水的 `setData` 不覆盖搜索结果。
