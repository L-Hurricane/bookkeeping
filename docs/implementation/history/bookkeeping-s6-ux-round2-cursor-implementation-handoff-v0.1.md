## 1. 单 Coding Agent 在获批范围实现

**UI-FB-010 净值折线**：替换柱状图为按北京时间日期的日终账本净值折线；基于 S4/现有统计 API 的真实确定性历史数值，每日最后生效业务事件后数值，无交易日沿用上一日；截止今天仍是今天业务日终的已保存事项口径，不等于当前这一秒或包含未来的当前账面余额。转账双方分别按各自业务时间生效，余额调整采用已保存固定差额；时间/账户/归档筛选继承原行为。明确数值、日期及异常退化；不能以美化图表为由改账务语义或客户端伪造财务序列。若现有 API 缺失，先评估是否能在已有只读聚合范围低成本补齐；正式 Schema、新账务算法/冻结事实变化须 STOP。

**UI-FB-011 单账户流水**：按已确认原型统一账户标题/净值卡片、历史月末与本月截至今天日终数值、收支摘要、月份、搜索、分组流水、FAB；可读性与不同长度数字适配；全部分类/交易返回路径维持原行为。**删除单账户流水底部的退出登录（前轮 FB-008 漏项）**以及冗余说明；不移除必要错误风险或永久删除影响提示。交易点击直接编辑，余额调整历史只读可删除、归档历史只读，转账双侧符号正确。

**UI-FB-012 筛选 + 分类/标签管理样式**：把预设日期、更多的自定义日期/归档/自选账户做层次分明的统一组件；两个管理页改为一致的列表、行动菜单、主次操作，删无用的标签说明；保持删除前影响和确认。

**UI-FB-013 分类/标签树移动**：做可用的触屏拖动层级操作，提供点击手柄选择目标上级的等价备用交互。实际依赖后端既有 move API 和业务校验：禁止循环/移到自己或后代、最多三级、移动子树超深、分类跨收入/支出、已有直接关联交易的分类成为父节点；标签移动不改变显式关联和交易内容。可从一级移动回合法二级，错误提示明晰并恢复 UI 选中状态。**不要承诺没有持久化依据的兄弟顺序拖动**，不要自行新建排序字段或迁移。若当前后端在合法操作上存在缺陷，先记录复现与最小修复界限，超出批准范围则停止该部分并报告。

**UI-FB-014 记账表单 + 账户选择**：沿用视觉原型的浅色卡片和金额主区，收入/支出切换、提交/取消明确；账户列表改为内容自适应高度的底部弹层、内部可滚动、多账户不遮挡可达操作；账户名/类型/余额和当前选择清晰。保持账户上下文默认、保存回到所属账户、标签多选/取消、分类叶子/可不选；转账仍是单独表单。不新增 MoneyWiz 多类别、交易状态/对方。

**金额与其它**：明确带符号的流水、账户余额、净值及变化一律正红负绿零中性；继承已经批准的“分类/标签聚合显示中性色”例外，不扩大颜色业务语义。已延期的账户自定义分组和逐笔余额继续不做。其余首页、统计目录、AI 入口、“我的”沿用前轮已批准实现，不无故翻修。
