## 1. 第二轮待确认的五项反馈

| 编号 | 负责人现场问题 | 本次预览的推荐设计 | 核验边界 |
|---|---|---|---|
| UI-FB-010 | 净值柱状图不合适；希望按每天最后一笔交易结算后的净值呈折线 | 细折线与轻填充，选中日期可看数值，期初/期末/变化三栏保留；按北京时间业务时间的**每日日终 as-of 净值**展示 | 同日事件按正式流水顺序，转账双业务时间分别入账；无交易日延续前日日终值；截止日期以统计筛选为准，未来业务时间不得提前进入历史值。优先复用 S4 既有真实历史净值能力，不用“当前余额”倒推，不另建持久化表；实际 API 计算能力待 Cursor 核验。|
| UI-FB-011 | 单账户流水页风格和新首页不一致，解释文案多 | 账户资金卡片 + 本月收支/历史月末余额三栏 + 日期分组卡片式流水；搜索/月份切换/FAB 布局协调；删除基础解释文案与账户流水中的退出登录入口 | **点击交易仍直接进入可编辑表单**，不能改为只读详情；归档历史只读，余额调整保留独立行为；行金额按其实际符号正红负绿。示例不包含逐笔余额 UAT-03。|
| UI-FB-012 | 时间/账户筛选控件与分类、标签管理的操作按钮粗糙、不统一 | 筛选独立卡片，时间预设、日期范围、归档开关、自选账户分区；分类/标签管理以统一图标、行内操作、独立新增入口替代四个竖排大按钮；标签冗余说明删除 | 保留现有筛选含义；正常与归档范围不混淆；正常无风险操作可简洁，删除等真实风险提示不得取消。|
| UI-FB-013 | 分类/标签节点调为一级后难以再移回二级，提议参照拖动管理 | 同一树形管理组件，右侧手柄拖动；为小程序触屏与无障碍场景补充“点击手柄选择新上级”的等价操作；可从一级合法回到二级 | 严格遵守 PRD CT-01～CT-10：不成环、移动整棵子树不能超三级；分类不可跨收入/支出类型，**目标父分类不得已有直接交易关联**；标签允许父子各自被交易显式关联，不擅自改动已有交易关联；不能删除有子节点的节点。实际拖动事件与后端拒绝、冲突恢复需测试。|
| UI-FB-014 | “记一笔”表单仍丑；账户选择底部弹层空白大、缺乏产品感；参考 MoneyWiz | 表单顶部金额主视觉、收入支出切换、必要字段按卡片分组、明确保存；账户选择改成**内容自适应高度、可滚动的底部弹层**，行内展示账户名/类型/当前余额/选中勾选；不在弹层堆空白 | 使用既有字段，不增加多类别、交易对方或状态；收入支出同表单、转账独立；名称可选，分类未选亦可保存，选中分类必须是当前叶子，标签显式多选、父子可同时选；不能选择归档账户。编辑删除规则不变。|

## 3. 交互与测试要求（获批后才用于 Cursor）

1. **金额与时间正确性**：折线数据按照每天截止到北京时间该日日终的确定性账本净值，不通过 UI 假算，不能以柱状图修改名义改变统计 API 口径；需用合成家庭账本验证有/无交易日、同秒排序、跨月转账双时间、余额调整和已保存未来时间。
2. **账户流水布局**：余额、当月收支、月末数据和交易列表在不同数字位数下不挤压；搜索/月份与账户设置保留；旧说明文字及账户流水底部退出登录消失。
3. **筛选与层级操作**：自选账户恢复时条件一致，含归档开关明确；分类层级可以一级⇄二级移动，拒绝非法深度/循环/直接关联交易的目标父类；标签移动不影响交易已经选中的父子标签集合。
4. **表单与弹层**：旧表单可用字段无缺失；账户选择采用紧凑弹层，账户多时只在弹层内部滚动；不同来源正确默认账户；不要向归档账户新增交易。
5. **质量 Gate**：复用现有 S6/T07/T08 的必要定向独立 Testing/Supervisor，不增新 Gate，仍由负责人作为用户做 T08 最终判断。保护 `bk_s6_family_e2e_20261027` 的 owner 试用数据，回归用 auto；无新的正式 Schema/生产库/真实数据或外部模型调用，剩余一次真实模型仅可由负责人亲自点击。不得 Push/合并 main/部署。
