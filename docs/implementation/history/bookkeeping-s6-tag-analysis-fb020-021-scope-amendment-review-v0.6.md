## 1. 用户场景与目标（负责人已确认）

1. 事件：`2026年旅游` 标签的全部花费、旅游中 `孩子` / `妻子` / `外卖` 分别花费多少。
2. 按期间：本月 / 本季 / 本年等时间范围内，`孩子` / `妻子` / `外卖` 各花费多少。
3. 一笔交易允许多个标签，金额在**不同查询之间可重复**；但同一查询内必须按交易 ID 去重，标签并非金额分摊。不得把孩子与妻子的标签金额直接相加宣称为旅游总额。
4. 第一阶段只做明确的**单标签与交集（AND）**场景，不加入 OR 可视化、任意表达式、项目管理、预算、现金流、报表引擎或标签金额分摊。保留分类/标签独立且等权的既有分析入口。

## 2. 与正式 PRD 冻结业务语义的关键差异

| 项目 | 原正式口径 | 目标 / 兼容策略 |
|---|---|---|
| ST-09 标签子树 | 任一标签及后代显式关联交易 **并集**，单个子树内按交易 ID 去重 | 原样保留；每个单标签仍按子树并集去重 |
| ST-09 已有多标签选择 | **多个所选标签子树先做并集、再按交易 ID 去重（OR）** | **不可把既有接口隐式改为 AND**。保留旧接口语义兼容；新增显式 `同时包含`（AND）查询能力，具体参数/API 以 Cursor 源码核验后的只读技术方案为准 |
| ST-08 标签占比 | 分母始终为相同收支类型、时间、账户范围的全体净总额绝对值；允许交叉、不必和为 100%，零分母不可计算 | 标签概览及覆盖率继续保持；AND 结果另有**标签组合结果金额/笔数/分类构成**，必须分别标注分母，不能将组合占比冒充原 ST-08 覆盖率 |
| 页面 | 标签行“加入多选/取消多选”，顶部“查看所选标签”，语义不明 | 替换为点击单标签进入详情，并在详情明确「同时包含其他标签」；旧 OR 业务能力保留于服务兼容层，若去除既有 OR 前端入口须列为明确冻结 UI 差异，不得静默删除能力 |
| 时间 | 常用自然月/季/年、滚动窗口与自定义 | 标签详情继承进入时的时间/账户筛选，候选增加「全部时间」以分析完整项目（查询性能/上限必须真实测试）。AI 月/年筛选不变 |

**AND 计算定义（待实现时验证）**：设选中主体标签 A 的交易集合为该标签及其全部后代显式关联交易并集 `S(A)`；每个附加标签 `B_i` 同理形成 `S(B_i)`。分析结果为 `S(A) ∩ S(B_1) ∩ ... ∩ S(B_n)`，按交易 ID 去重后按带符号金额聚合。用户未选附加标签时结果等于 S(A)。同一笔关联父子标签、多个子标签时不能多算。只筛选当前登录用户、已选账户、收入/支出、业务时间；转账/余额调整不计入普通收支。

**分类构成**：在上述过滤后的交易集合上按现有互斥分类/未分类规则汇总；构成项合计须与该组合的净收支金额一致；带符号与零/负净额沿用 ST-07 的安全退化。列表/图表聚合金额仍沿用已批准的中性色例外，具体流水金额正红负绿。

## 3. 拟议交付与版本差异

**A：现行 S6-T06 范围内可以先执行的 UI 改善（FB-020）**
- 分类环形图：可点击扇区高亮，显示名称、金额和正确占比；对应分类列表支持继续下钻。
- 标签横向条：可点击条或行高亮，显示标签名称、金额和正确的覆盖率；不因标签重叠误导比例之和必为 100%。
- 图表数值、名称、下钻均取现有真实统计数据，不能用演示数据或仅客户端重算替代后端事实；无法得出可靠图形与点击关系时给出降级说明，避免虚假命中。

**B：须在本 Review 独立批准后才能开始新增 Coding 的功能（FB-021）**
- 标签列表移除含义不清的「加入/取消多选」文案与顶部「查看所选标签」，以明显的「查看标签」进入单标签详情；为已保存的 OR 统计口径保留兼容，不暗改原接口。
- 标签详情提供**当前时间/账户范围的金额、笔数、按分类构成、查看关联交易**，明确显示所选标签范围（含子树/直接标签查看规则）。
- 「同时包含其他标签」选择面板：从已有标签树显式多选，已选标签以可删除的条件展示；每追加一个按 **AND** 缩小查询；允许取消，结果和交易分页继承条件。
- 事件跨期场景候选「全部时间」，**仅在复用既有索引/查询且实测可接受时实施**；否则标明性能风险并留待专项判断，不新增 Schema/历史 Flyway 修改。
- 收入/支出两端支持同一交互；不可新增其他统计维度或扩建通用报表引擎。
