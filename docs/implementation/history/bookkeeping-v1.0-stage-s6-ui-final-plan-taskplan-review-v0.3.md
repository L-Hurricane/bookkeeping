## 1. 目标和原则

S1～S5 已完成主要业务能力开发，但不等于用户已体验整合后的完整产品，也不等于发布就绪。**S6 首要目标是把冻结的产品 UI 真正落地，保证核心业务从页面入口可达、可操作、可回归；体验调整排在这一目标之后。**

明确两个有先后顺序的工作段：

**工作段 A：冻结 UI 实现和基础功能核对（优先、必做）**

- 兑现已确认的主导航 **账本 / 统计 / 我的**；账本及归档账户入口、交易/转账/余额调整路径；分类和标签管理的账本级入口；统计按 **账本净值 / 收入分析 / 支出分析** 分区，收入/支出的分类、标签**独立且等权**，保留筛选、下钻和显式标签多选；统计二级全账本 AI 自然月/年入口。
- 金额**正红、负绿、零中性**；交易流水点击直接编辑并保留删除入口；修改交易后返回所属账户流水；归档账户只读；已保存的 BalanceAdjustment 仍然只能查看、删除再重建，不新增编辑功能；转账双业务时间、统计口径、AI 持久化/额度和永久删除方案 B 均保持已批准业务语义。
- 解决冻结 UI 明确不符的遗留：`UI-NAV-01/S1-T08-OBS-01`、`S3-UI-ENTRY-01`（以原始 Backlog 为准）、`S4-UI-COPY-01`（“净资产”改“账本净值”）、`S5T06-D1`（EMPTY_PERIOD 明确提示）。必要实现与局部文案不视作 UI 升级。
- 在可合法使用、可恢复且不含真实数据的 UAT 环境中，进行必要的 Coding 自测、受影响回归和可运行预览；提供一份**简短基础功能体验清单**，让负责人先自行观察完整产品，反馈核心流程是否有问题。这里是按负责人要求的**试用/问题收集**，**不新增一个独立的正式质量 Gate，也不视为最终人工 UAT PASS**。

**工作段 B：基于实际使用反馈的体验优化（后置、条件性）**

- 在工作段 A 具备可运行预览后，再评估 `UX-ST-01`，可参考 MoneyWiz，但不能照搬其报表/投资功能。
- 已冻结 UI 不变的样式、反馈与操作细节（C 类）由组长在范围内决定；若要改变冻结导航、页面关系、操作逻辑、旧单账户 AI 可见入口，或增加 `UAT-03` 逐笔后余额等超出原冻结规则（B 类），**必须先提交具体 UI/产品差异、影响和验证说明，经负责人独立批准后才能编码**。不产生必要差异时直接不做 B，不为了“升级 UI”创造工作量。
- 升级不得改变已通过的账务事实、统计口径、租户隔离、AI 额度/报告或删除行为。完成后进行必要回归，再进入独立 Gate 和最终统一人工 UAT。

## 2. 冻结与延期范围

**本 Stage 必做**：冻结 UI 的缺口实现；在小程序里能从完整业务主路径操作 S1～S5 已有功能；必要的非阻断 UX/文案修复；受影响功能回归；T07 独立 Testing/Supervisor；T08 **一次** v1.0 最终正式人工验收；T09 结项及现有 Git 交付。

**不默认实施**：MoneyWiz 式全新报表体系；移除旧单账户 AI 入口；逐笔交易后余额 `UAT-03`；其他新 PRD 功能。以上是仅在证据与批准支持下可讨论的候选，不是本 Review 的必交付 Coding 范围。`UX-ST-01` 先通过实际使用定位根因，未确认必须改冻结 UI 前仅留可复核建议。

**不纳入**：生产部署、公众发布、新 Schema/历史数据迁移、未经批准的数据库/模型真实调用、平台工具建设、未经授权工作区清理、Agent 合并 `main`、新共享 PR 或强推。

### 工作顺序与人为接入最小化

1. **T00～T05** 是优先完成的冻结 UI 完整交付工作包；组长可在依赖内调整普通任务组织，单 Coding Agent 串行。达到安全可用预览后邀请负责人**看一次基本功能**，不在功能未稳定时要求审新 UI。
2. **T06** 才讨论实际体验反馈与可选 UI 调整；只对**确实偏离冻结基线**的具体 B 类差异请负责人决定，其余自主完成或延期。T05 试用不是额外正式 Stage Gate；T07、T08 保持各一次，不降低既定独立性与人工验收。
3. 若 T05 发现核心功能缺陷，优先修复并验证；非阻断的“更美观 / 更像 MoneyWiz”不抢占修复预算。冻结交付范围、人工最终 Gate 和正式产品/UI 变更仍是负责人保留边界。

## 4. 实测与安全要求

- **财务业务不可回归**：交易 CRUD/归属、余额调整固定历史事实、转账两侧业务时间、负/零余额、归档与永久删除、三级分类、标签父子多选去重、净值和统计筛选；金额正红负绿零中性。
- **AI 不以未验证冒充稳定**：S5 已有 Stub + 受控 V18 隔离 MySQL 集成证据，真实外部 AI 及微信真机仍延期；只可用符合授权的合成 UAT 数据。V18 未获授权部署到 `bookkeeping`、`bookkeeping_test` 或真实/生产库，T05 不擅自运行会触发自动迁库的 Spring 配置。
- **测试事实分层**：Coding 自测、独立 Testing/Supervisor、负责人试用反馈、正式最终人工 UAT 各自留证；没有真实执行就标为未测；GitHub checks=0 不是 CI PASS。
- **STOP**：Stage 计划未批即编码；冻结产品/UI 差异未经批准而实施；P0/P1 未闭环；库身份/恢复不可确认；真实业务数据或外部模型超出授权；不可逆/越权 Git 操作；独立/最终 Gate 未通过却结项。
