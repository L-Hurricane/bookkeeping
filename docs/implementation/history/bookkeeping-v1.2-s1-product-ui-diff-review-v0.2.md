## 2. C11 点名覆盖

本 v1.2 候选仍只覆盖下面两句旧规则：

- `docs/domain/v0.1-domain-model.md` 中「编辑只能修改名称、金额、分类、标签、业务时间和备注」。
- UI-FB-014 已批准记录中的「不增加交易对方」。

覆盖只在普通支出生效：

- 新建、编辑、清空、详情展示。与交易名称、分类、备注分开保存，互不覆盖。
- 不进入流水搜索、统计、商户管理、联系人管理。
- 收入、转账、余额调整不增加这个输入。收入请求若带非空对方，拒绝，不静默丢弃。
- 详情页显示已保存文本。账户流水行、月汇总和统计不显示、不筛选该字段。
- 日常新建和编辑不读取 Excel，也不改已有交易的对方。

数据库列、API、幂等选择路径和恢复方案见 `docs/implementation/history/bookkeeping-v1.2-c11-counterparty-schema-review-v0.2.md`。那里的 DDL 仍是 **NOT APPROVED**。正式 Schema 与 Stage Plan 都获批后，才可以在已授权隔离环境创建并验证 V21。个人正式库执行是另一项授权。

## 3. 历史回填

历史回填单列为待授权专项。它不构成本 Task 的数据操作，也不随本 Review 的批准自动执行。

匹配顺序如下，不清库、不重导：

- Excel「描述」对应数据库交易名称。首选账户、描述、业务时间。
- 同一条件对上多笔时，再用分类、金额和类型分辨。类型必须是支出。
- 只有一对一的支出可以写入「交易对方」。对不上、对上多笔或不是支出的行保持原样。
- 先出匹配报告。负责人看过报告后另行批准，再由负责人在本机执行。

本文件不授权读取 Excel、连接个人库、生成生产匹配报告或执行 UPDATE。Cursor 不接触个人数据、凭据或备份。

## 4. 不改数据事实的展示

这些句子是本 Stage 的验收句。已提交 UI 差异 v0.2 的 SHA 见文首，只作来源核对。

- C05 只改单账户流水行的显示符号和类型文字。余额增加为正红，减少为负绿。行上保留收入、支出、转入、转出、余额调整。信用账户不因账户类型再翻转一次。库存金额、余额公式、编辑提交值、月汇总和统计图不变。颜色按显示出来的数学符号。
- C02 的普通收支、转账转入、转账转出、余额调整共用一套编辑。原生日期选择器只接收已经规范的 `YYYY-MM-DD`。改日期保留秒；「现在」带秒；原生时间选择器把秒写成 `00`。不合法输入不能绑到选择器，也不能保存。
- C06 保留进入表单前的全部时间、月份、自定义起止、搜索和分页。用新记录 id 定位。记录不在当前筛选内时不改筛选。不新增按 id 查页的接口，除非后续页数证明现有游标不够。
- C03/C08 复用已有 `display_order` 与分组 API。各组可独立展开。拖到页面上下边缘时滚动。拖动过程中其他卡片让位，松手才保存。失败时恢复服务器顺序。
- C04 搜索仍按名称。归档账户仍不可选。两侧仍不能是同一账户。无新账户字段。
