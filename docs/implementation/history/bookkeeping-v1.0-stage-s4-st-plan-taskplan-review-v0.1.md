## 1. Stage 目标、交付范围和排除

**独立可验收目标**：完成微信小程序账本内三项统计：净值变化、支出分类/标签分布与明细、收入分类/标签分布与明细。落实 PRD **ST-01～ST-10 全部 P0 口径**，与 S1～S3 已交付的多账户、两侧转账时间、余额调整和三级分类/标签树兼容。

**必须交付**：
1. ST-01：统计三模块，收入/支出分类与标签同等入口。
2. ST-02：本月、本季度、本年、自定义时间区间（北京时间自然边界），合法起止日期和跨期处理。
3. ST-03：默认全部正常账户，可选全部账户、单个或自定义多选；归档账户显式可选；已永久删除不可选；明细继承筛选。
4. ST-04～05：所选账户历史时点净值、期初/期末/净值变化与合理趋势；账户信用负值抵减；普通交易/余额调整按业务时间，转账出入两侧各自按业务时间；**历史时点净值**与含未来保存记录的**当前账面余额**分开命名与计算。
5. ST-06：收入、支出分开、带符号金额；起始金额、转账、余额调整不计收支。
6. ST-07：分类按最新三级树归属汇总、同一交易归属一个当前叶子或“未分类”、上卷不遗漏；金额与分类总额守恒。带符号占比＝分类带符号金额÷对应净总额绝对值；净额负数、零分别按 PRD 处理。
7. ST-08～09：标签以该标签及所有后代显式关联的交易并集、**交易 ID 去重**计算；标签间可重叠、比例固定以相应全范围收支净额绝对值为分母；父标签下钻提供“直接关联本标签”，多标签筛选取子树并集后去重；零净额不输出虚假比例。
8. ST-10：分类/标签“总体→下级→交易明细”统一下钻，树变化按当前结构解释历史；标签分组可重叠，不误导为可简单相加；筛选继承；保持已冻结金额**正红负绿**及直接进入流水编辑等语义。

**排除**：AI-01～AI-07 全账本月/年 AI 功能；V18 在其他数据库的迁移操作；已延期 `UI-NAV-01/S1-T08-OBS-01`、`S3-UI-ENTRY-01`（最晚 v1.0 最终 UI Gate 处理）；`UAT-03`；未批准新基础设施、报表功能、备份平台、生产部署、共享 PR、新的独立流程门禁、工作区清理。现有可达页面入口可复用，不以此 Stage 改变冻结主导航，但必须保证统计页面可以从现有合法入口实际访问并完成全部 ST 交互。

## 4. 代表性验收样例及 STOP

1. **分类**：同一期间支出餐饮 400、交通 300、未分类 300，总支出 1000，对应 40%/30%/30%；三级叶子上卷后不遗漏或重复。分类汇总与总净额守恒。
2. **负与零净额**：净总额 80、两类金额 100 和 -20，占比分别 +125% 和 -25%；净额负数时代数占比和 -100%；净额 0 不给占比值。
3. **标签**：同一交易 100 同时显式关联父「旅行」与子「北京」，「旅行」子树仅算 100；「直接关联本标签」只包含对父标签的显式关联；标签间占比允许超 100%。
4. **跨期转账**：转出与转入时间跨日期/月份、仅一侧在时点前时，净值可出现短暂变化；当前账面余额仍包含已保存的未来事实。
5. **筛选/权限**：默认正常账户，多选、主动包含归档后统计变化正确；永久删除账户不可选；明细继承筛选；不同用户数据不可穿透。
6. **趋势/空态**：期初/期末净值与所选范围各账户历史时点余额相符；空账户/空区间/无交易仍可合理展示。

**STOP**：冻结 PRD/UI 冲突、须新增正式 Schema/DDL、未知真实/敏感数据操作、不能确保未提交工作树可恢复、跨租户读取、账务/统计严重错误、P0/P1 未关闭、需越权远端 Git 或清理、独立 Gate/人工 UAT 未通过、需要更改已批准人工 Gate 或 Stage 范围。出现 STOP 时局部暂停并由组长报告具体保留审批题及最小替代，其他不受影响的合法任务可继续。
