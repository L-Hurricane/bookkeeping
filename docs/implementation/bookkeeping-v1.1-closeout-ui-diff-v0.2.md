## 2. C11｜普通支出的可选「交易对方」

负责人 2026-11-09 将此项列为必交付。它和下列已冻结句子冲突，只在本项生效：

- `docs/domain/v0.1-domain-model.md` 中「编辑只能修改名称、金额、分类、标签、业务时间和备注」。
- UI-FB-014 已批准记录中的「不增加交易对方」。

覆盖范围：

- 仅普通支出。新建、编辑、清空、详情展示。
- 与交易名称、分类、备注分开保存，互不覆盖。
- 不出现在流水搜索、统计、商户管理、联系人管理。
- 收入、转账、余额调整不增加这个输入。收入请求若带上非空对方，拒绝，不静默丢弃。
- 日常新建和编辑不读取 Excel，也不改已有交易的对方。历史回填是单独的待实施方案，见下节，当前未授权。

详情页显示已保存文本。账户流水行、月汇总和统计不显示、不筛选该字段。

此项的数据库列见 Stage/Task Plan v0.2。那里的 DDL 候选 **NOT APPROVED**。未获专项批准前，不改表，不改 API。

### 历史回填（待实施，未授权）

组长已接受 C11 的字段设计为候选。历史值以后可以按下面的规则回填，但本文件不授权读取 Excel、匹配或写入任何正式交易。

- 不清空正式交易，也不重新导入。
- Excel「描述」对数据库交易名称。首选复合条件是账户、描述、业务时间。
- 同一条件对上多笔时，再用分类、金额和交易类型分辨。
- 只有一对一唯一匹配的支出交易可以写入「交易对方」。对不上、对上多笔、或不是支出的行，保持原样。
- 先产生匹配报告。负责人看过报告后，另行专项批准，再由负责人在本机执行生产回填。

V21 Schema 候选仍是 **NOT APPROVED**。回填方案也不提前批准那次 DDL。
