**M1 / S2-1**：账户归档、从正常列表移除、归档管理、历史与余额只读、恢复、写入/编辑归档账户关联记录前须恢复，归档不改变账务事实和派生余额。同步试验两个仓库外轻量模块：A 已批准 Task 启动入口、B 只读证据汇总。**M1 自动 Testing + 实质独立 Supervisor 全 PASS 后可形成子里程碑自动门禁通过结论；随后须立即暂停，向负责人完成简短复盘与管理确认，不能径行启动 M2**。M1 不强制微信人工功能 UAT，但须明确真机/UI 未验证范围。

## 4. 两个子里程碑的验收清单

### M1 自动子里程碑（独立自动 PASS + 必须负责人管理确认）
- 正常账户归档后不在正常列表，归档账户仍可查看历史记录、余额，恢复后重回正常列表。
- 归档不删除、不重算既有源记录，不改变当前余额；同用户账户重名约束仍按 PRD。
- 归档账户不可新增普通交易、转账（转账功能尚未建成时作为后续回归条件）、余额调整；不得编辑涉及归档账户的旧普通交易，恢复后可以操作。
- 拒绝跨用户访问及写入；后端并发、异常退出不可留下部分业务事实。
- S1 相关后端与小程序回归结果有证据、独立 Testing 和 Supervisor PASS；测试排除项清楚。
- A+B 统计真实负责人消息/脚本操作、手动上传次数、累计活跃分钟数、AI 轮次和新增脚本数；与 S1 可比部分比较，不能虚构精确基准。
- 微信开发者工具/真机体验**不作为 M1 必备 Gate**，相应未测 UI 风险在 M2 一并复验。
- **M1 停止/复盘 Gate（新增负责人明确指示）**：提供功能实际交付及未测内容、Testing/Supervisor 完整证明、A+B 对比 S1 的真实人工交接次数/活跃时间及问题、是否建议 M2 保留工具。组长报告后须等待负责人明确确认，**不得因 M1 自动 PASS 擅自开始 M2**。

### M2 人工总里程碑
- A→B 转账 1000：A -1000/B +1000、不计入普通收入支出；转出 17 日、转入 18 日分别按自身日期影响历史时点，允许相反业务时间；修改金额/账户不生成第二笔稳定 Transfer ID。
- 双侧转账流水时间与排序、账户归档不可参与转账、整笔删除两边资金同时撤销；所有金额按符号红/绿规则。
- 归档账户永久删除前能够准确预览原交易、调整、转账数量、受影响账户及删除前后余额；用户确认后一次事务完成，版本变化需要重新预览确认。
- 涉及仍存在账户的转账被整笔删除且余额、历史流水/统计一致；不能留下孤儿转账或外键阻断；用户隔离正确。
- M1 功能未回退，S1 `OBS-01` 仍按其另行批准的最迟 Gate 跟踪，不能将其遗漏或谎称 S2 修复。
- 负责人可从原日常项目目录检出已审 UAT 分支开展微信开发者工具人工验收，不覆盖脏文件或强制清理 worktree。
- 同时 Review 自动化流程是否减轻人工交接，决定 A+B 保留或停用；展示 PR #2（保持 Draft）、SHA、测试和 CI 缺口。
