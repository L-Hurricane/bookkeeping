## 2. 合成家庭数据集 v0.1

### 用户与规模

- 一个独立的合成账本登录身份，由**一位成年人记录全家**（两位成年人、一个孩子）的资金往来；不需要家庭多人协作。
- 固定随机种子、数据集版本、时区 `Asia/Shanghai`；推荐覆盖 2025-11-01 至 2026-10-27（共约 12 个月，当前月只生成截至今日、**绝不制造未来已发生消费**）。
- 每个完整自然月约 **450～550 笔消费交易**，当前月按已过去的天数等比例缩放；另有规律性工资、零散兼职和必要转账/余额调整，总体约 6,000 笔上下。数量只是容量目标，不能为了凑数破坏记账语义。
- 现金流符合城市工薪家庭的合理范围：两笔固定工资合计约 30,000～40,000 元/月、兼职收入间歇发生约 1,000～5,000 元/月；房租、水电、教育、超市、餐饮、通勤、通讯、人情、医疗、出行和小额高频消费有合理日期规律和偏差。节假日、月初/末有少量峰值。
- 多账户：银行储蓄、另一储蓄、微信、支付宝、信用账户、现金，以及一个可归档账户；账户期初值合成。包含负余额但不把信用额度计入净值。
- 覆盖三级分类、未分类、显式父/子标签多选、同一笔多标签、无标签、跨月/跨年转账（转出转入双业务时间）、余额调整、回溯补录、归档/恢复、同秒多笔交易及边界日期。永久删除使用**专门的小样本可丢弃测试身份**，不破坏长期试用账本。
- 数据均为虚构，禁止导入真实人名、联系方式、银行/支付账号、备注或身份标识。测试身份与业务用户及真实数据完全隔离。

### 测试环境与恢复

- 使用**已授权、可明确识别、专用且非真实数据**的隔离开发/UAT 环境；不得默认为 `bookkeeping`、`bookkeeping_test` 或曾用于 V18 演练的 `bookkeeping_migration_test` 可任意写入。
- 先核实环境归属、数据库白名单、当前版本及 Flyway 状态、逻辑备份/恢复脚本与演练。优先复用已知能力；需要新环境、越权对象或正式 Schema 时 STOP 按治理申请。禁止 `Flyway.clean`、危险 DROP、不可恢复覆盖与偷偷将 V18 迁入其他库。
- 生成器必须**幂等且有版本标识**，支持“创建一份新合成用户数据集”；不对不属于本次 run 的记录做修改/删除。不把保密凭据写进 Git。
- 先完成自动化验证和基线恢复演练，再把模拟家庭用户交给负责人自由试用。**负责人开始增删记录以后，任何批量重置都必须先征得其明确同意**；优先独立复制一份测试用户供 Agent 回归使用。
- 保存数据集清单、seed、完整导入行数/各类型数量、数据生成源码 SHA、基线摘要和恢复记录；不在 Project/Git 提交大体积带凭据的数据库备份。

## 3. 预期值：必须有独立 Oracle，不能自证正确

Testing 使用生成时的事件事实（非后端统计 API 的返回）独立计算并固定至少以下对照结果：

1. 各自然月全账本/单账户收入与支出，分类三级父子金额、未分类金额；收入支出不包含转账、余额调整。
2. 标签父子聚合按**交易 ID 去重**，无标签独立统计；不同顶级标签覆盖金额可以重叠，不能相加为账本总额。
3. 各账户期初、任意选择的历史月末余额及指定日历史净值；负余额参与净值抵减，所有金额使用分为单位的精确值，不用浮点近似作为判定依据。
4. 双时间转账在不同业务时点分别改变两侧账户余额；余额调整仅影响余额/净值，不增加收入支出；永久删除采用已批准的 AI 报告方案 B。
5. 自然月/年、滚动范围和自定义起止边界，北京时间的跨月跨年情况；归档账户默认排除、显式包含时正确计入。
6. 搜索的目标命中集及分页连续性；交易修改后余额、统计、图表和筛选结果需要正确更新。若 `UAT-03` 未获批，不将逐笔余额视为必须实现的断言。

要求至少保存 12 个自然月的账本聚合预期值，另抽取 20～30 个难例作为固定金标准；独立计算器不得直接复用待验证的生产统计/余额聚合实现。

| E02 | 首页账本净值、本月收入/支出、正常账户及归档入口 | 与独立预期值一致；金额正红负绿、零中性；已确认 UI 入口可达 |

| E04 | 12 个月分页/月份切换及简单模糊搜索 | 数据完整不重复，跨月命中与分页顺序稳定，不一次加载所有交易 |
| E05 | 新增/修改/删除交易后的一致性 | 余额、首页摘要、统计及下钻刷新；历史编辑后的派生结果正确 |
| E06 | 转账双业务时间、跨月/跨年、负余额 | 双侧时点正确；不污染收入/支出；显示符号和颜色正确 |
| E07 | 余额调整历史查看/删除重建、归档只读、恢复 | 遵守冻结业务规则，禁止编辑已保存余额调整 |
| E08 | 分类/标签管理、三级分类、未分类、无标签 | 操作与层级正确，标签父子多选并集去重；下钻与预期匹配 |
| E09 | 净值时间/账户筛选及走势图 | 期初/期末/变化和曲线样本精确，归档默认排除，自定义范围边界正确 |
| E10 | 收支环形图、标签横向条形图、百分比/零负分母 | 图表值与独立对账一致；不把重叠标签误当成加总 100% |
| E11 | 统计“查看期间交易”与分类/标签下钻 | 继承所选时间、账户、分类/标签条件，按需分页加载；多用户隔离 |
| E12 | 全账本 AI 的自然月/年、历史报告、额度、失败回滚与方案 B | 先使用 Stub + 独立 MySQL；区分已验证 Stub 与未验证真实供应商 |
| E13 | 重复提交、并发分页与错误返回 | 不会重复记账/重复扣配额、错误提示可理解，不产生不完整账务事实 |
| E14 | 数据规模与响应性能 | 约 6,000 笔规模下观察首页、月度列表、统计聚合、走势图和下钻的实际耗时、错误率和 SQL/HTTP 请求数量，先记录测量结果，**不臆造 SLA**；确有性能阻断才做有界优化 |
| E15 | 微信小程序自动化及视觉路径 | 先核实现有微信开发者工具可用的自动化能力；能自动化则运行脚本并留录屏/截图；不能自动化明确 `NOT AUTOMATED`，不得冒称完整微信 UI E2E PASS |
| E16 | 对已交给负责人的独立合成账户进行自由试用 | 负责人只判断业务功能、易用性和异常感受，最终给出正式 PASS/FAIL；不要求逐条比对账务预期 |

### 执行层级（避免伪 E2E）

- **层 1：独立预期值 + 真 MySQL + 生产服务/JDBC**，验证账务不变量和数据隔离。
- **层 2：真实 HTTP API + 会话/鉴权 + 数据库**，覆盖完整控制器和输入/输出契约，不能只跑 Java service 或 Mockito。
- **层 3：小程序 UI 自动化 + 后端 API + 隔离数据库**（工具真实可用时执行）；至少主导航、创建、保存、筛选、下钻及失败提示。不可执行的路径显式标 `NOT AUTOMATED`。
- **层 4：负责人自然使用 + 最终一次人工业务接受决定**，重点验证体验是否符合产品方向，而不是人工替代层 1～3。

## 5. 缺陷、验收与风险控制

- **P0/P1 阻断最终人工验收**：跨用户访问、账务/净值计算错误、错写数据、数据丢失、AI 配额绕过或危险删除；需要 Coding Agent 在获批范围内修复，并由独立 Testing 定向复验。非阻断 P2/P3 可按既定治理延期，明确最迟修复 Gate。
- 自动化完成条件：真实执行的场景记录环境、数据 seed/version、Git SHA、测试命令和计数、独立 expected/actual 对比、性能数据、失败截图/日志、恢复证明；输出简短汇总与完整可追溯证据。`PASS`、`FAIL`、`SKIPPED`、`BLOCKED` 严格区分。
- S6 当前已批 UI A01～A09 完成后，**新代码需要原 T07 的受影响独立 Testing/Supervisor 复验**；既有旧 HEAD 的 PASS 不覆盖新代码。负载数据及端到端测试可并入原 Gate 的执行内容和 T08 UAT 准备，不另建独立 Gate。
- **真实大模型是单独保留项**：`S6-AI-GEN-01` 须在 v1.0 最终 Gate 前，经费用/外部请求及数据范围明确授权，用纯合成财务数据完成真实生成→持久化→再读取（如需追加年度场景，单独写明请求次数）；在此之前 Stub PASS 不等于真实模型 PASS。
- 真实性质数据导入及任意生产库操作未获本方案授权；如负责人之后决定使用真实个人交易做附加测试，必须另行明确数据边界、安全与授权，不是本合成测试的前提。
- 不为测试引入 Redis、消息队列、通用 Agent 平台或独立 CI 基础设施；优先复用现有构建/测试命令和微信开发者工具。微信真机专项没有实际执行，不得写成已通过。

## 6. 交付到负责人手上的形式

1. 只需在其惯用 Mac 本地仓库/微信开发者工具中打开已通过自动验证的待验版本，使用一个已经填充完整的**合成家庭测试用户**；用户登录方式由已有安全机制支持，Agent 负责最少必要的交接，不传递密钥到公开文档。
2. 提供一页以内的“正常使用体验提示”：随手看看首页资金、月份切换、分类/标签、搜索、交易新增编辑、转账和统计趋势；不要求负责人按编号操作 E01～E15。
3. 提供测试结论摘要：哪些已经自动验证、哪些仅 Stub、哪些未测、是否有 P0/P1、关键性能有无异常、当前可试用条件。
4. 负责人自由录入的交易**不被下一轮自动化重置**。若需恢复原基线，先确认他希望保留还是丢弃自己新增的模拟记录。
