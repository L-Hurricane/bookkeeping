## 测试

通过：

- 旧 INSERT 省略新列时得到 `ACCOUNT + MONTH`，生成键等于账户 id。相同协调键第二次插入为 `1062`。
- 旧快照列清单可以插入同一身份的两个版本。按 `account_id` 查找能看见这两条，看不见 `LEGACY` 或 `LEDGER`。
- 旧列清单和新列清单把 `ACCOUNT` 配上空 `account_id`，两张表、各两次，都是 `3819`。没有留下 `ACCOUNT` 且空账户，也没有留下 `ACCOUNT` 且空协调键的行。
- `LEDGER + YEAR + '2025'` 的协调键为 `0`，重复插入为 `1062`。同一年份可以有两条快照。
- `YEAR` 配 `'2025-01'`、`MONTH` 配 `'2025'`、带尾部空格的年份、`LEDGER` 配非空账户、`ACCOUNT + YEAR` 都是 `3819`。
- 两条相同身份的 `LEGACY` 都成功，协调键都是 NULL。测试事务已回滚，库里仍只剩演练夹具的两条历史行。
- 作用域 CHECK 含 `account_id is not null` 和 `account_id > 0`。生成列是 `ACCOUNT -> account_id`、`LEDGER -> 0`、否则 NULL，不引用自增 `id`。
- 协调唯一键已替换旧唯一键。`idx_analysis_generations_account_scope` 和 `idx_analysis_snapshots_period` 都在。额度表和用户锁没有新列。

外键删除规则在信息库中显示为 `NO ACTION`。这是 V18 之前 InnoDB 对未写 `ON DELETE` 的既有外键的记录方式，本次迁移没有改这些外键。
