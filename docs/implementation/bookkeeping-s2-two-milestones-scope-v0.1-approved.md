| 子里程碑 | 已确认的交付范围 | 目标 Gate |
|---|---|---|
| **M1｜S2-1：账户归档/恢复 + A+B-lite 真实试验** | 账户可归档、从正常列表移除、在归档管理查看历史/余额并恢复；归档历史只读、阻止归档账户新增普通交易和余额调整/编辑关联业务（恢复后方可操作），归档不影响计算余额；复用现有账户状态字段的可能性由只读调查确认。**不在 M1 进行永久删除或完整转账新功能**。 | 覆盖 API/服务/DB 安全/前端状态/回归的独立自动 Testing PASS + Supervisor PASS；**可不强制负责人本阶段人工 UAT**，组长提供自动门禁证据、功能/交互差异说明与人工交接数量。 |

## 2. A+B-lite 的最低技术范围

- **A-lite**：复用 S1 已有一次性脚本/SDK/POC-2，在获批 Task ID、初版 Plan SHA、授权执行工作区和允许角色下，形成一个最小可复用启动入口；仅调用明确登记的任务命令；如果现有脚本已足够，不强造新平台。
- **B-lite**：复用日志、Diff、测试退出码、独立 Agent 报告、SHA 与打包能力，生成一致的 Manifest/证据目录和可一次性转交的报告；避免含 Token、凭据、真实业务数据和无关文件。
- **不做**：全自动 ChatGPT↔Cursor 通信、跨 Agent 自动放行、业务数据库执行代理、新服务/消息队列、UI 控制台、GitHub 安全绕过；不降低 Coding 单线程及独立测试/审核 Gate。

## 3. 对比与试验指标（S1 无全量人工耗时测量）

| 指标 | M1 应记录 | 验收倾向 |
|---|---|---|
| 负责人主动启动/复制次数 | Coding、Testing、Supervisor 的手动启动数，任务重试数 | 相对于 S1 同类工作减少，不以主观体感代替数据 |
| 负责人上传/回传次数 | tar.gz/文本结果/批准材料人工搬运数 | 有证据的一次性报告优先，不能虚称已自动回传至 ChatGPT |
| AI 执行与异常 | 调查、实现、自测、独立测试/审查的轮次及自然耗时 | 无界 SDK 调试则 STOP；优先交付功能 |
| A+B 维护成本 | 新增/修改文件数、重复脚本和后续复用难度 | 只限两个轻量能力；若重构 SDK 核心才可实现，则暂停 A+B 保业务优先 |
| 数据安全/质量 | 授权边界校验、错误任务/路径停止、SHA、独立测试、恢复演练 | 禁止任何 Gate 降级；M1 无人工 UAT ≠ 不测试 |

M1 Gate 回报必须包括**真实业务功能是否交付、实际自动测试结果、尚未验证的真实微信运行部分、旧/新方式人工交互对比、A+B 是否保留**。如果 M1 A+B 无实益，M2 可以回退现有低频人工脚本接力；无需为了完成试验继续投入。
