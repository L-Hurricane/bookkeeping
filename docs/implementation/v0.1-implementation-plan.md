# 1. Engineering Baseline / 工程技术基线

截至 2026-09-24，v0.1 采用：

| Area | Decision |
|---|---|
| Java | **Java 25 LTS** |
| Spring Boot | **4.1.1** |
| Build | **Maven Wrapper，Apache Maven 3.9.16** |
| Database | **MySQL 8.4 LTS 系列** |
| Migration | **Flyway，版本由 Spring Boot Dependency Management 管理** |
| Persistence | **Spring Data JPA + JdbcClient for explicit read queries** |
| Security | **Spring Security** |
| Password Hash | **Spring Security DelegatingPasswordEncoder，v0.1 使用 BCrypt** |
| API Test | **MockMvc + Spring Boot Test** |
| Unit Test | **JUnit Jupiter + AssertJ + Mockito** |
| DB Integration Test | **真实 MySQL 8.4 Test Database，不使用 H2 替代 MySQL 语义** |

## 1.1 Version Rationale

### Java 25 LTS

选择 Java 25 而不是本机现有 Java 23：

- Java 23 是非 LTS；
- Java 25 是当前最新 LTS；
- 适合个人长期维护；
- 与当前 Spring Boot 兼容；
- 不使用 Java 27 等非 LTS 作为项目基线。

### Spring Boot 4.1.1

使用当前 Stable 版本，不使用 milestone / snapshot。

### Maven Wrapper 3.9.16

统一通过：

```text
./mvnw
```

执行构建，避免依赖全局 Maven。

### MySQL 8.4 LTS

采用 MySQL 8.4 LTS 系列，不追 Innovation Release。

### Flyway

- 正式 Schema 全部由 Flyway Migration 管理；
- Hibernate 不负责正式建表；
- JPA Schema Generation 不作为 Migration；
- 工程阶段使用 `ddl-auto=validate` 或等价验证；
- Flyway 版本由 Spring Boot dependency management 管理，不单独手工锁版本。

# 3. Persistence Implementation Strategy

## 3.1 Write Side / Entity Persistence

使用：

**Spring Data JPA**

负责：

- User；
- Session；
- Account；
- Category；
- Tag；
- Transaction；
- Transaction-Tag Association；
- BalanceAdjustment；
- IdempotencyRecord。

Schema 始终由 Flyway 管理。

## 3.2 Read Model / Aggregation

Ledger、Balance、Monthly / Category / Tag Statistics 优先使用：

**Spring JdbcClient / explicit SQL**

理由：

- Query-time Aggregation 已冻结；
- Ledger 需要组合 Transaction + BalanceAdjustment；
- Statistics 是明确 Read Model；
- 显式 SQL 比复杂 JPA Entity Graph 更清楚；
- 不需要 CQRS Framework。

JPA 与 JdbcClient 共用同一个 MySQL DataSource 和本地事务边界。

## 4.1 Seed Strategy

### 不把真实用户名 / 密码写入 Migration

原因：

- 不应把真实凭证或固定密码哈希固化进 Git；
- v0.1 无公共注册，但预创建用户属于部署 / Bootstrap 数据。

### User Bootstrap

Phase 1 实现轻量 Bootstrap：

- 本地开发：从环境配置读取初始化用户名 / 密码；
- 正式部署：通过安全环境变量或一次性部署配置初始化；
- Password 原文不进入 Git；
- Bootstrap 必须幂等。

### Fixed Categories

Category 是 User-owned。

因此：

> 创建 Bootstrap User 后，同时幂等创建该 User 的固定 Category Set。

不做全局 Category 表，不在无 User 的情况下 Seed Category。

### Test Data

测试用户、测试交易、测试 Tag：

- 只存在于 Test Fixture / Test Setup；
- 不进入正式 Migration。

# 6. Module Dependency Rules

允许的高层依赖：

```text
identity      -> common

account       -> identity, common
category      -> identity, common
tag           -> identity, common

transaction   -> account, category, tag, identity, common
adjustment    -> account, identity, common

ledger        -> account, transaction(read contract), adjustment(read contract), common
statistics    -> account, transaction(read contract), category, tag, common
```

规则：

1. 模块不能依赖其他模块的 Controller；
2. 不直接修改其他模块内部 Entity；
3. 跨模块调用通过明确 Application Service / Read Contract；
4. Ledger / Statistics 只读，不反向修改 Transaction / Adjustment；
5. identity 不依赖业务模块；
6. common 不依赖任何业务模块；
7. v0.1 不引入 Spring Modulith Framework，只通过 package boundary、tests 和 review 维护边界。
