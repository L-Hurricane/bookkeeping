## UAT-06 余额调整读取失败

状态：**已修复**。P1，阻断人工 Gate 的是新建余额调整页。

页面文案「当前余额读取失败，请重新加载」来自 `balance-adjustment-create` 的 error 屏。参数无效会显示另一句「余额调整页面参数无效」，所以这次不是 accountId 没传到页面。请求是已登录的 `GET /api/v1/accounts`，服务端对缺省 lifecycle 只返回正常账户。旧代码在返回账户数不是 1 时直接当读取失败，不看 HTTP 是否成功，也不按传入的 accountId 取余额。多个正常账户时必然失败。这与本轮把账本页改成 `app.json` 第一页、归档后的 `reLaunch` 无关，那两处不改这条请求。

现在按 accountId 使用 `loadAccount` 的结果。命中正常账户才采用它的 `currentBalance`。找不到或响应不能识别时仍显示原来的失败，可以重试。已归档账户不打开调整表单，也不编造余额，页面提示恢复后才能继续。账户首页对归档账户本来就没有「余额调整」按钮。服务端 `requireWritable` 会拒绝归档账户上的新建和删除。历史详情仍可打开；归档账户详情为只读。

没有改 Schema，没有连接或改写数据库。
